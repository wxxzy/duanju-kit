# 00 · 学习路线与阅读方法

## 这一篇解决什么

在动手前先搞清楚：**这个工具到底替你做了什么，它不做什么**。很多人装完发现「这不就是 ffmpeg 套壳吗」，或者反过来以为它能自动下载素材、自动过平台审核——两种理解都跑偏。

---

## 它是干什么的

一句话：**把一批视频素材，按规则批量变成可投放的成片，全程只编码一次。**

「只编码一次」是核心。传统做法是：

```
切片 → 编码一次 → 加字幕 → 编码第二次 → 加片头 → 编码第三次 → 变速 → 编码第四次
```

每次编码都损失画质、都花时间。djkit 把这些操作全部翻译成 ffmpeg 滤镜，塞进**同一个 `filter_complex`**，一次解码、一次编码出结果。15 集素材的差距可能是 20 分钟和 2 小时。

它不干什么：

- 不下载、不抓取、不解析任何视频网站
- 不绕过平台查重（改 MD5、加噪点这类手法明确不做）
- 不替你判断素材有没有授权
- 不能把烂文案救成好文案（`script` 生成的稿子一定要自己看）

---

## 两条路线，别走混

### 路线 A：切片+包装

适合：有现成字幕文件，想快速出一批竖屏物料。

```bash
python -m djkit scan    授权素材/
python -m djkit rename  授权素材/ --apply
python -m djkit slice   授权素材/ --mode head --head 20 -o 切片/
python -m djkit fit     切片/ --burn-sub --sub-dir 授权素材/ -o 成片/
python -m djkit report  成片/ -o 台账.xlsx
```

这条路线里，**字幕是「别人给好的」**。`fit` 负责找到对应字幕、修正时间轴、烧进画面。

### 路线 B：解说片

适合：想做有旁白的二创内容，没有现成字幕。

```bash
python -m djkit hot       E01.mp4 --top 6            # 找高光
python -m djkit asr       E01.mp4 --lang en          # 转写（可选，用于了解剧情）
python -m djkit script    E01.txt --seconds 24 --variants 3 --context "人物关系与前情"
python -m djkit tts       文案/文案_A.txt --voice zh-CN-YunjianNeural
python -m djkit assemble  解说.yaml                  # 按文案现排字幕出片
```

这条路线里，**字幕是自己生成的**——因为文案在你手里，没必要让 Whisper 再听一遍。这是整个项目最值钱的设计判断，第 6 篇会详细讲。

两条路线不是非此即彼。实际生产中常见做法是：先用路线 A 快速测素材反应，爆了再做路线 B 的深度解说。

## 阅读方法：三层法

每篇教程都按三层写，读的时候可以按需停留：

| 层 | 内容 | 什么时候细读 |
|---|---|---|
| **能跑** | 命令和参数 | 第一次用，照抄即可 |
| **能懂** | 实现原理、为什么这么设计 | 要改代码、要调参数时 |
| **能改** | 坑、边界、测试断言 | 遇到异常、要扩展功能时 |

如果你只是想用工具，读到「能跑」这一层就够，直接看 README 的命令速查表。
如果想理解工程取舍（比如为什么字幕不走 ASR、为什么缺段一票否决），把「能懂」读完。
如果要二次开发，「能改」那部分才是重点——那里写了所有踩过的坑。

## 术语约定

| 术语 | 含义 |
|---|---|
| 素材 | 原始视频文件，未剪辑 |
| 切片 | 从素材里截出的短段（几秒到几十秒） |
| 成片 | 可直接投放的最终视频 |
| 花字 | 画面上的标题条 / 醒目文字，出现几秒 |
| 字幕 | 贯穿全片、与声音同步的文字 |
| 规格 | 输出分辨率，如 `1080x1920` |
| 画幅目录 | `整季/1080x1920/` 这种按规格分的目录 |
| 总纲 | 整季共用的人物、名词、设定汇总（`总纲.md`） |
| 配方 | 描述整条流水线的 YAML 文件 |
| 解说片 | 有旁白、按文案现排字幕的成片 |

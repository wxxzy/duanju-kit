# 01 · 最小可用：一条命令出片

## 这一篇解决什么

用最短路径跑通一次完整出片，顺便搞明白依赖是怎么装的、ffmpeg 从哪来。跑完这篇，你应该能把任意一段视频变成竖屏成片。

**主代码位置**：`djkit/core.py`（`ffmpeg_exe`、`run`）、`djkit/compose.py`（`cmd_fit`）

---

## 1. 安装

```bash
pip install -i https://mirrors.aliyun.com/pypi/simple/ \
    imageio-ffmpeg openpyxl tabulate pillow pyyaml
python -m djkit doctor
```

`doctor` 会检查三件事：

1. ffmpeg 找得到吗
2. libass 编进去了吗（烧字幕必需）
3. AI 三件套（faster-whisper / edge-tts / LLM 配置）装了吗

**为什么自带 ffmpeg**：`imageio-ffmpeg` 把 ffmpeg.exe 放在包内，不污染系统 PATH，也不用你手动下载。要走系统 ffmpeg 就设 `DJKIT_FFMPEG` 指向可执行文件。

看一眼 ffmpeg 从哪来：

```bash
python -c "from djkit.core import ffmpeg_exe; print(ffmpeg_exe())"
```

---

## 2. 第一次出片

准备一段测试素材（png 生成的彩条也行）：

```bash
python - <<'EOF'
import subprocess
from djkit.core import ffmpeg_exe
subprocess.run([ffmpeg_exe(), "-y", "-f", "lavfi", "-i", "testsrc=size=1280x720:rate=25",
                "-t", "8", "-c:v", "libx264", "素材/demo.mp4"], check=True)
EOF
```

跑最小命令：

```bash
python -m djkit fit 素材/ -o 成片/
```

默认行为：

- 规格 `1080x1920`（竖屏）
- 填充模式 `blur`（模糊背景，不是黑边）
- fps 25、crf 20
- 不烧字幕、不加 BGM

产物在 `成片/demo.mp4`。用 `python -m djkit doctor` 之外的方式确认结果：

```bash
python -c "from djkit.core import probe; from pathlib import Path; print(probe(Path('成片/demo.mp4')))"
```

应该看到 `width=1080, height=1920, has_audio=...`。

---

## 3. 加上全套参数

一次编码里能塞的东西比你想的多：

```bash
python -m djkit fit 素材/ \
    --specs 1080x1920,1080x1440 \
    --burn-sub --sub-dir 字幕/ \
    --title "他装穷三年 就为这一天" --title-style bar \
    --bgm 音乐.mp3 --duck --speed 1.1 \
    --intro 片头.mp4 --outro 片尾.mp4 \
    --cover auto \
    -o 成片/
```

逐项意思是：

| 参数 | 干了什么 |
|---|---|
| `--specs` | 一次跑两档分辨率；**配音和探测只做一次** |
| `--burn-sub` | 找同名字幕并烧进画面（详见第 3 篇） |
| `--title` | 开头 0.3 秒出现的标题条 |
| `--bgm --duck` | 循环 BGM，人声出现时自动压低 |
| `--speed 1.1` | 正片加速 10%，音调不变（atempo） |
| `--intro/--outro` | 自动规整片头尾的规格、帧率、音轨 |
| `--cover auto` | 从成片抽一帧做封面 |

**这些全部发生在同一次编码里**。第 4 篇会拆开看 ffmpeg 命令是怎么拼出来的。

## 4. Windows 下的便利入口

不想每次敲 `python -m`：

```bat
djkit.cmd scan 素材库/
```

`djkit.cmd` 会自动找 Python 并切 UTF-8 代码页——不加这句，中文路径在 GBK 终端下会乱码。`cli.py` 的 `_init_console()` 也做了同样的编码修正（调用 `SetConsoleOutputCP(65001)`），双保险。

## 5. 验证工具本身没坏

改代码之前，先跑一次自检建立基线：

```bash
python -m djkit selftest ./_自检
```

默认用**离线桩**：把 LLM 调用换成本地固定文案，把 edge-tts 换成 ffmpeg 生成的假音频。不联网、不花钱、30 秒左右跑完。

看到这一行就对了：

```
自检通过：94/94 项
```

自检会生成合成素材、跑完整流程、逐项断言。第 8 篇会讲它具体验证了什么——包括怎么用「数画面上的黄字像素」证明字幕真的烧进去了。

## 常见坑

**`doctor` 说 libass 不可用**
换 pip 装的 ffmpeg：`pip install imageio-ffmpeg --upgrade`。系统 ffmpeg 编译时未必带 libass。

**输出没有声音**
素材本身没音轨。`compose_cmd` 会自动补一条等长静音（`anullsrc`），保证后续 concat 结构统一，但成片确实是无声的。检查源素材：`probe(Path('素材/demo.mp4'))['has_audio']`。

**中文路径乱码 / 文件名变成问号**
在 Windows Terminal 或 PowerShell 里跑，别用老 `cmd.exe`。或者先 `chcp 65001`。

**`fit` 报「素材不存在」**
路径用相对当前工作目录的写法，或写绝对路径。`abs_path()` 统一处理，基准是命令里给的那个 `dir`。

## 小练习

1. 用 `--mode pad` 和 `--mode crop` 各跑一次，对比画面差别（模糊背景 / 黑边 / 裁切）。
2. 跑 `--specs 1080x1920,1080x1440`，确认两个文件都在，且体积差别合理。
3. 改 `--crf 28` 和 `--crf 18`，看看体积和画质变化。`crf` 越小画质越好、体积越大。

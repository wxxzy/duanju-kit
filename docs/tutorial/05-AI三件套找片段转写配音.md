# 05 · AI 三件套：找片段、转写、配音

## 这一篇解决什么

三个「智能」步骤其实只有一个真用了大模型。`hot` 是纯信号分析，`asr` 用 Whisper，`tts` 用微软的免费接口。搞清各自的原理和边界，才知道什么时候该信它、什么时候得人工兜底。

**主代码位置**：`djkit/hot.py`、`djkit/asr.py`、`djkit/script.py`（`llm_chat`）、`djkit/tts.py`

---

## 1. `hot`：不用 AI 的高光检测

很多人以为这里有什么多模态模型，其实是最朴素的信号分析。看 `analyze_motion()`：

**音频能量**：把音轨解码成 8kHz 单声道 WAV，按 0.5 秒一窗算 RMS：

```python
frames = pcm[:m*win].reshape(m, win)
rms = np.sqrt((frames ** 2).mean(axis=1))
```

**画面变化**：抽关键帧缩到 64×36 灰度，逐帧算平均像素差：

```python
diff = np.abs(np.diff(fr, axis=0)).mean(axis=(1, 2))
```

**打分与挑选**（`pick_highlights`）：

```python
score = 0.68 * pct(audio) + 0.32 * pct(motion)
```

音频占 68%、画面占 32%——**大声说话比画面切换更值得剪**，这个权重是试出来的。

然后按片段长度做滑动平均（避免选出「尖峰一秒」），排序取局部峰，按最小间隔去重。间隔太长挑不满时逐级放宽，但不低于 `0.6 × 片段长`（否则几乎重叠的片段会被当成两个候选）。

```bash
python -m djkit hot 素材/ --top 6 --len 8 -o 候选.csv
```

候选 CSV 可以直接喂给 `assemble`。GUI 里的「换一批片段」是把当前所有起点传给 `avoid` 参数，算法跳过这些位置——否则参数不变时结果是确定性的，点多少次都一样。

**这个方法的边界**：它找的是「热闹的片段」，不是「有意义的片段」。一段激烈但无意义的打斗会得高分。所以输出叫**候选**，不是成片，人要过一眼。

## 2. `asr`：faster-whisper 转写

```bash
python -m djkit asr E01.mp4 --lang en --model small.en -o E01.srt
```

同时产出 `.srt`、`.txt`、`.json`。模型缓存在 `~/.cache/djkit/models/`，第二次不再下载。

`ensure_whisper_model()` 会在首次使用时给出模型体积和耗时提示——GUI 里这一步尤其重要，否则界面看起来像卡死了。

**模型怎么选**：

| 模型 | 速度 | 专名准确率 |
|---|---|---|
| `small.en` | 快 | 科幻/奇幻专名错误率约 20% |
| `medium.en` | 慢 2–3 倍 | 明显好转 |

实测同一段音频：`small` 漏掉整句 `If more Klingons are on the way`，`medium` 听到了。

**结论**：总纲采样只用 7 分钟/集，用 `small` 够；真正影响成片的是文案，发现名字错得离谱时才值得换 `medium` 重跑。

`extract_audio_16k()` 先把音轨压成 16kHz 单声道再喂 Whisper——这是 Whisper 的推荐输入格式，能省不少内存。

## 3. `script`：LLM 写文案

```bash
python -m djkit script E01.txt --seconds 24 --variants 3 \
    --context "外星人入侵六个月后，汤姆是历史老师，小儿子被抓走…"
```

配置写在 `~/.djkit/llm.yaml`（别提交到仓库）：

```yaml
base_url: http://你的接口/v1
api_key: sk-xxxx
model: qwen3_6
```

也可以用环境变量 `DJKIT_LLM_BASE` / `DJKIT_LLM_KEY` / `DJKIT_LLM_MODEL` 覆盖。

**两个必须知道的实现要点**：

1. **关掉思考模式**。qwen3 这类推理模型默认会先长篇思考，约束一多就在 `reasoning_content` 里反复复述要求、把 `max_tokens` 耗光，正文一个字都不出。配置里加 `chat_template_kwargs: {enable_thinking: false}`，不认的服务返回 400 会自动回退重试。

2. **字数必须硬性约束**。只说「约 103 字」模型会写 50 字。要写「必须写满 5–9 行，总字数 87–118 字」，并给出每行 10–18 字。

`--variants 3` 一次生成三版，分别用「悬念开场 / 人物处境 / 反常识判断」三种角度。第 6 篇讲怎么从中挑一版。

> 不给 `--context` 时文案会空泛——台词本身就那几句。给了人物关系和前情，8 行 102 字念出来 23.7 秒，和目标 24 秒几乎重合。

## 4. `tts`：配音

```bash
python -m djkit tts 文案.txt --voice zh-CN-YunjianNeural --rate "+2%"
```

走 edge-tts，**不需要 API key**（用的是微软语音的公开接口）。

| 音色 | 特点 |
|---|---|
| `zh-CN-YunxiNeural` | 男声年轻，通用解说（默认） |
| `zh-CN-YunjianNeural` | 男声低沉有力，悬疑/末世 |
| `zh-CN-XiaoxiaoNeural` | 女声亲和 |
| `zh-CN-XiaoyiNeural` | 女声活泼 |

`cmd_tts()` 会先清掉 markdown 强调符（`**` 会被念成「星号星号」）和时间码前缀，可以把 ASR 生成的 `.txt` 直接丢进去。

**语速和字数的关系**：估算按 4.1 字/秒。`--seconds 24` → 目标约 98 字。TTS 实际语速会有偏差，第 6 篇讲怎么用配音时长反推画面时长，把误差吃掉。

## 5. `series`：整季总纲

做整季解说时，每集独立生成会出三个问题：第 8 集还在重新介绍主角、10 条视频互不相干、同一个人每集叫不同的名字。

```bash
python -m djkit series "素材/某剧 S01" --model small.en --lang en --minutes 7
```

`sample_windows()` 每集均匀采样 7 分钟（可改），拼成一段采样音频转写。`build_glossary()` 和 `summarize_episode()` 让 LLM 从采样里攒出人物表和名词表。

结果写到 `总纲.md`，后面每一集写文案时自动带上。

**两个必须知道的限制**：

1. **总纲写错一个设定，后面每一集都跟着错**。这是它唯一的风险，必须人工看一遍。
2. **人物关系会编**。采样只有 7 分钟/集，模型看到「被关起来」就往「囚犯」上写——实测把舰长写成了「克林贡囚犯」。现在提示词里卡了「只能写分集记录里明确写到的关系，看不出来就留空」，但仍然隔着一层 ASR。**人物表当参考，别当事实**。

译名错了用 `--names "原名=译名"` 一次性钉死，优先级最高：

```bash
python -m djkit series 素材/ --names "Michael Burnham=迈克尔·伯纳姆,USS Shenzhou=神舟号"
```

改完只重汇总不重转写（`--remix`），1 分钟搞定。

## 常见坑

**首次转写卡住不动**
在下模型。`whisper_ready()` 会检查模型缓存，没有就在日志里说明体积和耗时。

**文案里出现「本期视频」「接下来我们看看」**
模型爱写这类出戏词，提示词里禁不掉。第 6 篇的打分器会对这些词扣分并给出理由。

**音色念数字很慢**
TTS 念「2026年」比念中文词慢，字数估算会偏。用 `--rate` 微调，或把数字改写成中文。

**`hot` 选出来的片段都差不多**
参数不变时算法是确定性的。GUI 的「换一批」或 `avoid` 参数能跳过已选位置。

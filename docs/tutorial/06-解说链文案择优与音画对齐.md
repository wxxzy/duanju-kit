# 06 · 解说链：文案、择优与音画对齐

## 这一篇解决什么

一次生成三版文案，到底选哪版？选定后配音念出来 23 秒、画面只有 20 秒怎么办？字幕为什么不需要 ASR？

**主代码位置**：`djkit/score.py`、`djkit/align.py`、`djkit/subtitle.py`（`build_script_srt`）、`djkit/assemble.py`

---

## 1. 三版文案，为什么是三版

`script --variants 3` 用三个不同开场角度写同一段剧情：

- **A 悬念开场**
- **B 人物处境**
- **C 反常识判断**

差别全在开头几句。三版的差别不在「字数多少」，而在「钩子是什么」——所以并排看开头就能判断。

GUI 里有「并排看」：三列只读视图，点哪列切哪版。每版改过的内容各自记着（前端 `varEdits`），切走切回来不丢，也不会污染另外两版。

---

## 2. 择优：从「字数接近」到六维打分

原来的选法是「字数最接近目标」。不够，因为：

- 字数对得上，但**少写一段**——三段画面只配了两段词
- 字数对得上，但全是 7 字短句——念出来像念标签
- 字数对得上，但两句完全重复
- 字数对得上，但混进了「本期视频」——直接出戏

现在的 `score.py` 用六个维度加权：

| 维度 | 权重 | 怎么算 |
|---|---|---|
| 覆盖 | 0.30 | 有词的段数/总段数。**缺段砍到 ratio×40**，不是线性扣分 |
| 字数 | 0.24 | 偏差 0→100；30%→40；≥50%→0 |
| 句长 | 0.14 | 落在 8–24 字的句子占比 |
| 重复 | 0.14 | 去标点后逐句比，重复率≥30%→0 |
| 出戏词 | 0.06 | 命中「本期/大家好/点赞关注」等 → 每个扣 1/3 |
| 可念 | 0.12 | 含英文长词、markdown 残渣的句子占比 |

**覆盖为什么是「一票否决」**：少一段，那一段画面就废了，字写得再漂亮也补不回来。所以写满才给 `ratio×100`，缺段直接砍到 `ratio×40`——乘上 0.30 的权重，缺一段基本赢不了。

调用方式：

```python
from djkit.score import rank
best_key = rank(versions, want_chars=98, n_seg=3)
```

`rank()` 就地给每个 version 写回 `score / grade / score_parts / reasons / best`。界面上的三列评分明细就是 `score_parts`，扣分理由来自 `reasons`。

**几个细节**：

- `grade` 分档是「扎实 / 可用 / 凑合」，**不带「推荐」**。推荐徽标只给 `best` 那一版，保证全局唯一。早先的 bug 是三版分数打平时三个都标「推荐」。
- 理由必须是人话：`句长：2 句偏短（均值 7 字）` 比 `line_len=0.62` 有用得多，用户看到「缺 1 段（那几段画面会没词）」会立刻去补。
- 分数是**相对**的，只在同批候选之间比较。全都很差时仍然选分高的，但会提示「几版分数接近，建议并排看一眼」。

**为什么不调模型来评**：本地打分不花钱、不联网、毫秒级、结果稳定。择优标准是几条明确规则，规则能写成代码就不该烧 token。真要看文采，人看三列并排比任何模型打分都准。

## 3. 字幕：不走 ASR 的设计判断

这是整个项目最值钱的一个判断。

解说片的字幕内容**你本来就有**——文案在手里，每段画面时长也在手里。那就没必要「先念一遍再听回来」。

`build_script_srt()`：

```python
def build_script_srt(seg_scripts, durations, dst, *, start_at=0.0, width=16):
    cues = cues_from_scripts(seg_scripts, durations, start_at=start_at)
    return write_srt(cues, dst), len(cues)
```

三个关键设计：

1. **时间按字数分配**，不按段平均分。字多的句子本来就念得久，平均分会导致字幕跑在语音前面。
2. **折行按 16 个汉字一行、最多两行**，优先在标点处断开（`wrap_cjk`）。libass 不会自动换行，必须自己做。
3. **短于 0.55 秒的条目并进上一条**，否则一闪而过反而看不清。

比 ASR 好在三点：**专名一个都不会错**（`汤姆` 不会被听成 `汤母`）、**不用等转写**、**时间轴天然对齐**（时间是从文案和时长算出来的）。

`assemble.py` 里有两条字幕通道，别搞混：

| 配置项 | 时间轴基准 | 用在哪 |
|---|---|---|
| `片段[].字幕` | 该片段在成片里的起点 | 老素材切片（字幕是整集的，要平移） |
| `字幕`（顶层） | 整条成片 | 解说片（SRT 按文案现生成，天生对齐） |

烧制顺序是**花字先、字幕后**：花字在画面上方、字幕在下方，一上一下不冲突。

## 4. 音画对齐：配音反推画面时长

这是解说片的另一半。看 `align.py`：

```python
def build_aligned_voice(audios, targets, dst, work):
    """把每段音频补齐静音到目标长度，再拼成一条"""
    for a, tgt in zip(audios, targets):
        dur = probe(a)["duration"]
        pad = max(0.0, tgt - dur)
        # apad=pad_dur 补静音，-t 截到目标长度
        run([... "-af", f"apad=pad_dur={pad:.3f}", "-t", f"{tgt:.3f}" ...])
```

**补齐而不是直接拼**：`assemble` 只认「一条配音 + 一串带时长的片段」。只要这条配音的分段边界和视频片段边界严格重合，就等于逐段对齐了。

concat 清单必须用绝对路径：

```python
lst.write_text("".join(f"file '{p.resolve().as_posix()}'\n" for p in parts))
```

相对路径是相对**清单文件所在目录**解析的，会拼成 `产出/E01_A/.../产出/E01_A/...` 这种重复路径。

`fit_segments()` 处理「配音比画面长」：

```python
if need <= avail:
    target = max(2.5, need)
else:
    # 音频太长：加速，最多 1.6 倍
    ratio = min(1.6, dur / max(0.5, avail - tail))
    ...
```

**宁可加速配音，也不拉长画面**——画面一旦超出源素材可用范围就黑屏了。

反过来，`assemble_cmd` 里处理「配音比画面长」是延长最后一段（用更多原片，而不是冻结最后一帧）：

```python
if voice_dur > total + 0.2:
    extra = voice_dur - total
    room = max(0.0, avail - dur)
    extend = min(extra, room)
    if extend > 0.05:
        seg_info[-1][2] = dur + extend
```

两条路径方向不同：`fit_segments` 是**提前规划**，`assemble_cmd` 是**兜底修正**。

## 5. 混音层级

解说片里声音的优先级：

```
配音（满）> 原声（0.12）> BGM（0.2 且被人声闪避）
```

配音出现时原声必须让路，否则听不清旁白。`assemble_cmd` 里：

```python
if voice and src_vol is None:
    src_vol = 0.12
```

`0.12` 是默认值，配方里可以用 `原声音量:` 覆盖。

## 常见坑

**三版分数打平，三个都标「推荐」**
已修。徽标只由 `best` 决定，`grade` 不带「推荐」二字。

**字幕和语音差半句话**
时间轴是按字数分的，不是按 TTS 实际发声点。差得多说明 `--rate` 和估算差太大，或文案里混了很长的数字/英文（TTS 念这些比字数估算慢）。量小不用管，量大就把 `--rate` 往回调。

**配音尾部被截断**
`assemble_cmd` 会打印警告。减少片段或加快语速——不要试图冻结最后一帧凑时长，观感很差。

**配音拼接后分段边界对不上**
检查 concat 清单是不是绝对路径。这是 `align.py` 里专门修过的坑。

## 小练习

1. 造三版文案，一版缺段、一版全是短句、一版混了「本期视频」，跑 `rank()` 看分数和理由。
2. 用 `build_script_srt()` 生成 SRT，检查时间码是不是按字数分配（长句占更多时间）。
3. 故意让配音比画面长 3 秒，跑 `assemble` 看末段自动延长的日志。

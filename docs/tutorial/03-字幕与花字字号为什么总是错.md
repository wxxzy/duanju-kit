# 03 · 字幕与花字：字号为什么总是错

## 这一篇解决什么

为什么写了 `FontSize=20` 在 1920 高的画面上变成巨型字？为什么国内找的 SRT 全是乱码？为什么切片后字幕时间对不上？这三个坑覆盖了字幕问题的九成。

**主代码位置**：`djkit/subtitle.py`、`djkit/title.py`

---

## 1. 字号：libass 用的是脚本坐标，不是像素

这是最容易踩、也最难自己想明白的坑。

libass 内部有一个虚拟画布，`PlayResY` 默认是 **288**。滤镜里的 `FontSize` 是相对这个 288 的坐标，不是输出画面的像素。所以：

```
FontSize=20  →  20 × (1920 / 288) = 133 像素  ← 巨型字
```

`build_sub_style()` 做反向换算：

```python
def build_sub_style(style, out_h, size_px, font):
    scale = 288.0 / out_h          # out_h 是输出高度
    font_size = size_px * scale
    ...
```

所以命令行写 `--sub-size 64`，意思就是**输出画面上 64 像素高**，不管你是 720p 还是 1080p 还是 1920 高的竖屏。内部自动换算。

**花字同理**，见 `title.py` 的 `build_title_filter`。`--title-size 96` 是 1920 高度下的 96 像素。

---

## 2. 编码：国内 SRT 大量是 GBK

libass 只吃 UTF-8。国内网站下载的 SRT 很多是 GBK / GB18030，直接喂进去要么乱码、要么整条不显示。

`read_text_any()` 按 UTF-8 → UTF-16 → GB18030 → Big5 的顺序试，命中就用对应编码解码，再统一写回 UTF-8：

```python
def read_text_any(p: Path) -> tuple[str, str]:
    for enc in ("utf-8-sig", "utf-16", "gb18030", "big5"):
        try:
            return p.read_text(encoding=enc), enc
        except (UnicodeDecodeError, UnicodeError):
            continue
```

**注意 `utf-8-sig` 不是 `utf-8`**：前者会吃掉 BOM。带 BOM 的 SRT 用 `utf-8` 读，第一条字幕开头会多一个不可见字符，样式错乱。

平移后的字幕写进 `.djkit/sub/`，不覆盖原文件。

## 3. 时间轴平移：切片后字幕为什么对不上

把整集字幕烧到 5–11 秒的切片上，如果不处理，画面第 1 秒出现的会是整集第 1 秒的台词。

`slice` 生成的文件名带 `_p01_5s-11s`，`slice_range_of()` 从里面解析出起点 5 秒。`prepare_sub_file()` 做两件事：

1. 所有时间码减 5 秒
2. 裁掉落在 `[0, 6]` 之外的条目

`shift_sub_text()` 负责实际改写。看它的边界处理：

```python
# 完全在段外的丢掉
if t_end <= offset or t_start >= offset + duration:
    continue
# 跨边界的裁剪到段内
t_start = max(0.0, t_start - offset)
t_end = min(duration, t_end - offset)
```

**平移后可能一条都不剩**（比如你切的是片头，那段没台词）。`resolve_sub()` 检查文件大小 `< 20` 字节就返回 `None`，不拿空字幕去烧——libass 遇到空字幕文件会报错。

> 别在 `slice` 和 `fit` 两步都开 `--burn-sub`，会烧两遍，字会重影。

## 4. `SubIndex`：字幕匹配的顺序

`--sub-dir` 给多个目录时，`SubIndex` 按这个顺序找：

1. 同目录同名
2. 同 stem（`demo.mp4` → `demo.srt`）
3. 剧名 + 集数
4. 宽松包含

跑之前会打印 `字幕匹配 3/20`。一条都配不上时工具会提醒——不要忽略这个提醒，继续跑只会得到无字幕的成片。

---

## 5. 花字和字幕的分工

两者都是画面上的文字，但设计上完全不同：

| | 花字 | 字幕 |
|---|---|---|
| 时长 | 几秒 | 贯穿全片 |
| 位置 | 通常上方 | 通常下方 |
| 内容 | 标题、钩子 | 与声音同步 |
| 实现 | `title.py` drawtext 滤镜 | `subtitle.py` libass |
| 样式 | `--title-style` | `--sub-style` |

`--title-style` 可选 `hook`（白字黑边）、`bar`（半透明黑底条）、`yellow`（黄字）、`redbar`（红底白字）。

花字太长会自动缩字号（`wrap_and_fit`），缩到 18px 就不再缩——再小也看不清，这时候该改文案而不是继续调参数。

`fix_orphan()` 处理孤字：一行末尾只剩一个字时把它挪到上一行，视觉上舒服得多。这种细节是「能用」和「好用」的区别。

---

## 6. 字幕格式的一个致命细节

`write_srt()` 写标准 SRT 时，条目间必须有空行，**末尾也必须有空行**：

```
1
00:00:00,000 --> 00:00:02,500
第一句

2
00:00:02,540 --> 00:00:05,000
第二句

← 这个空行不能少
```

少一个末尾空行，libass 的表现是**不报错、就是不出字幕**。这比直接报错难查得多。自检里专门有一条断言检查这个格式。

## 常见坑

**字幕是方框/豆腐块**
字体缺字。`--sub-font "Microsoft YaHei"` 或 `--sub-font "SimHei"`，别用英文字体。`doctor` 会检查系统字体。

**字幕位置全错**
多半是字幕文件和视频不是同一版片源。用播放器对一下首句出现时间，整体平移字幕文件——工具不负责校正这种内容层面的偏差。

**花字挡住人脸**
`--title-pos top` 挪到上方，或 `--title-y 0.25` 直接给纵向比例。底部要留出字幕位置。

**改了 `--sub-size` 没反应**
确认同时开了 `--burn-sub`。`--sub-size` 只在烧字幕时生效。

---

## 小练习

1. 造一个 GBK 编码的 SRT，跑 `fit --burn-sub`，确认不乱码。
2. 用 `--sub-size 32` 和 `--sub-size 96` 各烧一次，量一下画面上字的实际高度（应该是 32px 和 96px）。
3. `slice --mode ranges --ranges "10-18"` 再 `fit --burn-sub`，看字幕是不是从原片第 10 秒开始的。

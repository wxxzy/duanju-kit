# 08 · 测试与交付：自检、打包与排错

## 这一篇解决什么

怎么证明「字幕真的烧进去了」而不是只看了一眼？怎么把工具打成一个 340MB 的文件夹让别人双击就能用？改完代码怎么快速回归？

**主代码位置**：`djkit/selftest.py`、`djkit.spec`、`launch.py`、`打包exe.bat`

---

## 1. 自检不是打日志，是带断言

```bash
python -m djkit selftest ./_自检
python -m djkit selftest ./_自检 --live   # 走真实 LLM/TTS
```

默认用**离线桩**：

```python
def _install_stubs():
    script.llm_chat = fake_llm        # 返回固定文案
    sys.modules["edge_tts"] = FakeTTS # 用 ffmpeg 生成等长静音
```

整条链的编排逻辑都能测，不产生 API 费用。

现在跑 **16 个阶段、94 项断言**：

| 阶段 | 验证什么 |
|---|---|
| scan / fit / slice / report / rename | 基础命令的产物和时长 |
| assemble / hot | 拼接时长、候选 CSV 行数 |
| 解说链 | 成片规格/音轨/文案，**成片长度 ≈ 配音长度** |
| 冒烟 | 13 条子命令 `--help` 全正常 |
| 剧集总纲 | 采样、别名合并、译名替换 |
| 界面 | 规格解析、进度恢复、缓存白名单 |
| 文案择优 | 缺段一票否决、六维理由、推荐徽标唯一 |
| 字幕 / BGM | 下面详说 |
| 整季汇总 | 集数/画幅/时长/缺音轨缺封面/台账 |
| 抽帧 | 每阶段产物留证 |

`Checker` 类累计通过/失败数，失败返回非零退出码——可以挂 CI。

## 2. 没有图像识别，怎么证明字幕烧进去了

这台机器上没法用视觉模型，也听不了音频。所以改成**可量化的证据**。

**字幕：数像素**。用 `color=c=black` 生成纯黑底视频，烧黄字字幕，抽一帧成 rawvideo rgb24，逐像素数：

```python
# 黄色判定：R>190, G>190, B<100
if r > 190 and g > 190 and b < 100:
    n += 1
```

结果：**有字幕 4597 px / 无字幕 0 px**。

早期用 `testsrc` 当背景失败了——它本身有大量黄色，带字幕 21183 px、不带 20106 px，差值淹没在噪声里。换纯黑底才得到干净对照。

**BGM：比响度**。用 `volumedetect` 过滤音轨，从 stderr 里找 `mean_volume` 行：

```python
re.search(r"mean_volume:\s*(-?[\d.]+) dB", line)
```

结果：**纯静音 −91 dB → 混入 BGM −35 dB**，差 56 dB。

`volumedetect` 有个坑：`mean_volume` 出现在 `histogram` 之后，而且 `-f null -` 和 `NUL` 的行为不同。逐行扫含 `mean_volume` 的行、取 `]` 之后的内容才稳。

**这类断言比「看起来没问题」可靠得多**。它不依赖人眼、不依赖听感，改了代码一跑就知道有没有弄坏。

## 3. 前端怎么测

没有 playwright，`msedgewebview2.exe` 也不支持 `--headless=new --screenshot`（SIGTERM）。

解法：**Node.js 极简 DOM 模拟**。把 `app.js` 读进来，用 `new Function` 注入假的 `document`/`window`/`fetch`：

```js
const api = new Function("document","window","fetch","setTimeout","clearTimeout",
  code + "\nreturn { renderSeason, renderVarTabs, renderScoreTable, setS };")(doc, ...);
```

假的 `El` 类实现 `innerHTML` / `textContent` / `appendChild` / `className`。然后直接调渲染函数，断言 DOM 结构：

- 三版评分 UI：3 个标签、3 列评分、**推荐徽标唯一**、扣分理由显示、单版时整体隐藏
- 整季汇总：状态行 `✓ 2 集 · 01:24 · 23.9 MB`、2 张卡片、无音轨/无封面标红、画幅 chip 高亮、空数据隐藏

这样能在没有浏览器的情况下验证前端渲染逻辑。

## 4. 打包成 exe

```bash
打包exe.bat
# 等价于
python -m PyInstaller djkit.spec --noconfirm
```

产物 `dist/djkit/djkit.exe`，整包约 **340 MB**，one-folder 结构：

```
dist/djkit/
  djkit.exe                       ← 双击这个
  _internal/                      ← 解释器 + 依赖 + ffmpeg + 页面
    djkit/web/                    ← index.html / app.js / style.css
    imageio_ffmpeg/binaries/...   ← ffmpeg
    ctranslate2/ctranslate2.dll
  gui_out/                        ← 首次启动自动创建
```

### 为什么是 one-folder 而不是 one-file

- one-file 每次启动要把 340MB 解到临时目录，冷启动 20 秒起
- one-file 临时目录每次都变，webview 的 `storage_path` 跟着变，等于每次启动都丢本地状态
- one-folder 出问题时能直接看到 `_internal` 里少了哪个 dll

### 打包后必须改的三处路径

判断条件是 `getattr(sys, "frozen", False)`，见 `gui_server.app_root()`：

| 位置 | 源码运行 | 打包后 |
|---|---|---|
| `gui_server.OUT_ROOT` | `cwd/gui_out` | `exe 所在目录/gui_out` |
| `gui_server.HERE` | `djkit/` 源码目录 | `_internal/djkit/` |
| `run_explainer` 的 base | `Path.cwd()` | `OUT_ROOT.parent` |

不改的话产物会落在 `C:/Windows/System32/gui_out` 之类的地方——取决于你从哪儿双击。

### 几个坑

- **`console=False` 后 stdout 是空的**。`launch.py` 里不判断 `is None`，frozen 时一律把 stdout/stderr 换成 `gui_out/app.log`。否则双击闪退一个字都没有。
- **UPX 必须关**。压过的 `ctranslate2.dll` 会报「不是有效的 Win32 程序」，报错位置和真因差很远。
- **webview 后端是动态加载的**。必须写进 `hiddenimports`：`webview.platforms.edgechromium`、`webview.platforms.winforms`、`clr`、`pythonnet`。
- **imageio-ffmpeg 的 ffmpeg 在 `binaries/` 下**，普通二进制收集扫不到，要用 `collect_data_files`。
- **excludes 排除 Qt / pandas / matplotlib / scipy**。不排体积翻倍，且 Qt 会和 pywebview 抢 GUI 后端。
- **`multiprocessing.freeze_support()` 必须调用**，否则依赖新起进程时无限递归开新 exe。
- **`collect_submodules("djkit")` 全量塞进去**。项目有十几处函数内 `import`（为了少加载模型），静态扫描跟不到，漏一个就是运行时 `ModuleNotFoundError`。
- **PyInstaller 的 COLLECT 会删旧 `dist/djkit`**。文件数超阈值可能触发工具层的批量删除保护而失败。解法：先把旧目录 `mv` 挪开，让 PyInstaller 新建。
- **exe 运行中会锁住 `dist/djkit`**。重新打包前必须 `taskkill /F /IM djkit.exe`。

### 打完包怎么验

```bash
dist\djkit\djkit.exe
type dist\djkit\gui_out\app.log
```

日志里应该有三行：

```
ffmpeg   ...\_internal\imageio_ffmpeg\binaries\ffmpeg-...exe
[app] 服务已起：http://127.0.0.1:xxxxx/
[app] 桥接就绪，页面已连上（pid xxxxx）
```

第三行最关键——它是页面里的 JS 主动调 `ping()` 打回来的，等价于「窗口没白屏、桥能用」。

还能直接用 HTTP 验接口：

```bash
curl -s http://127.0.0.1:xxxxx/api/season     # 应 200
curl -s "http://127.0.0.1:xxxxx/cover?p=C:/Windows/win.ini"  # 应 403
```

## 5. 常见问题速查

| 症状 | 原因 / 解法 |
|---|---|
| 字幕烧了但一条没出来 | 检查 SRT 末尾空行；检查 `字幕` 不是 `off` |
| 字幕是方框 | 字体缺字，`--sub-font "Microsoft YaHei"` |
| BGM 报文件不存在 | 相对路径基准是 `_work/`，写绝对路径或让 GUI 先 `resolve()` |
| BGM 忽大忽小 | 先把 BGM 统一到 −16 LUFS，比调音量有效 |
| 花字没出现 | `--title-start` 相对正片起点，不含片头 |
| 三版分数都很低 | 改 `--seconds` 或把 `--context` 写详细点重跑，别硬选 |
| 转写名字错 | `--names "原名=译名"` 钉死，或换 `medium.en` |
| 重打包失败 | 先 taskkill，再把旧 dist 目录挪开 |

## 结语

这个项目里反复出现的三个原则，值得带走：

1. **能算出来的就别再测一遍**。字幕不 ASR、择优不调模型、探测走缓存——能确定的事不花钱重试。
2. **失败要留证据**。日志、断言、抽帧、签名文件——别让用户对着白屏猜。
3. **改东西别破坏旧行为**。配方没写字幕就不烧、缓存按内容签名失效、目录不存在也返回完整字段——向后兼容是默认选项。

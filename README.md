# djkit — 短剧二创 / 推广素材工具

给做短剧推广、二创的人用的本地视频流水线。一条命令完成：**改规格 + 烧字幕 + 变速 + BGM 混音 + 拼片头片尾 + 出封面**，全程只编码一次。

往上还有一层：**整季解说片**。从素材到成片是「找片段 → 转写 → 写文案（三版择优）→ 配音 → 按文案排字幕 → 出片 → 汇总」，
图形界面把这套流程包成四步，命令行用一条配方也能跑完。

> **它不是什么**：它**不含任何下载、抓取、解析功能**。素材必须是你自己有权使用的——剧方下发的授权素材包、推广平台后台下载的成片、或你自己拍摄制作的内容。

**想系统学一遍？** 看 [docs/tutorial/](docs/tutorial/README.md)——9 篇递进教程，从「一条命令出片」到「为什么字幕不走 ASR」再到「exe 打包踩过的坑」，按实现顺序讲，每篇都带代码位置和常见坑。

## 一、先解决"素材从哪来"

没有授权，后面所有步骤都是白做。

| 类型 | 说明 |
|---|---|
| 剧方 / 出品方直签 | MCN、制片公司 BD 直接下发素材包，最稳，通常附授权书和投放范围 |
| 短剧推广平台 | 右豹、星子助推等第三方推广平台，注册后可申请剧目推广资格与素材包 |
| 平台官方推广任务 | 抖音巨量星图 / 快手星芒等短剧推广计划，任务页里直接给成片素材 |
| 番茄 / 红果官方合作 | 官方推广合作入口，走商务对接 |

（入口和名称各平台会调整，投放前以当期官方文档为准。）

判断素材"能不能剪"：有明确授权范围；拿到的是成片或素材包而非自己录屏；清楚必须保留的标识。

**本工具刻意不做"规避平台查重"的功能**。改 MD5、加噪点、变速抖动、加扫描线这类手法，是平台判定搬运作弊的典型特征，一旦识别直接限流封号。

## 二、安装

```bash
pip install imageio-ffmpeg openpyxl tabulate pillow pyyaml
python -m djkit doctor
```

Windows 下也可直接跑 `djkit.cmd`（自动找 Python，已切 UTF-8 代码页）。

自带 ffmpeg（imageio-ffmpeg，不污染系统）。想用系统 ffmpeg：设 `DJKIT_FFMPEG` 指向 `ffmpeg.exe`。烧字幕依赖 **libass**，`doctor` 会检测。

AI 三项（`asr` / `tts` / `script`）的依赖单独装，国内走镜像：

```bash
pip install -i https://mirrors.aliyun.com/pypi/simple/ faster-whisper edge-tts
```

### 代码结构

按职责分模块，命令入口统一在 `cli.py`：

```
  media.py       命名识别、扫描、Clip

  title.py       花字 / 标题条
  compose.py     成片合成（规格 + 字幕 + 变速 + BGM + 片头尾）
  slicer.py      批量切片

  asr.py         语音转写
  script.py      解说文案（LLM）
  score.py       文案 A/B/C 本地打分（六维、可解释）
  tts.py         配音
  align.py       配音与画面时长对齐
  explainer.py   解说片一键流水线（配方里 `解说:` 那条链路）
  series.py      剧集总纲（采样 / 转写 / 汇总）
  season.py      整季成片扫描与汇总
  recipe.py      配方流水线
  report.py      投放台账
  selftest.py    自检 + doctor

```

依赖单向：`core → 领域模块 → 命令 → cli`，没有循环引用。

## 三、基本命令

### 1. `scan` — 摸清家底

```bash
python -m djkit scan 素材库/
```

递归扫描，自动识别**剧名 + 集数**，读时长/分辨率/体积，首尾哈希查重，输出控制台表格 + `_素材清单.csv`（UTF-8 BOM，Excel 不乱码）。

能认的命名：
```
某剧_第03集.mp4     某剧_EP03.mp4     某剧 03.mp4
某剧-03-1080p.mp4   03.mp4（放"某剧组"文件夹里也能认）
```

### 2. `rename` — 规范命名

```bash
python -m djkit rename 素材库/            # 预演
python -m djkit rename 素材库/ --apply    # 执行
```

统一成 `剧名_003.mp4`，冲突自动加 `_dup2`，改完在 `.djkit/` 留撤销记录。

### 3. `slice` — 批量切片

```bash
python -m djkit slice 素材库/ --mode head --head 20 -o 切片/     # 每集开头 20 秒
python -m djkit slice 素材库/ --mode even --seg 30 -o 切片/      # 每 30 秒一段
python -m djkit slice 素材库/ --mode ranges --ranges "0-15,62-78" -o 切片/
```

输出 `切片/剧名/剧名_EP003_p01_0s-20s.mp4`。`--copy` 快 10 倍但切点吸关键帧、可能差零点几秒，投流素材建议重编码。

### 4. `fit` — 成片合成（核心）

```bash
# 只改规格
python -m djkit fit 切片/ --mode blur --size 1080x1920 -o 成片/

# 全套：字幕 + BGM + 变速 + 片头尾 + 封面 + 双规格
python -m djkit fit 切片/ \
    --burn-sub --sub-dir 字幕/ \
    --bgm 音乐.mp3 --bgm-vol 0.25 --duck \
    --speed 1.1 \
    --intro 片头.mp4 --outro 片尾.mp4 \
    --cover auto --cover-sizes 720x1280 \
    --specs 1080x1920,1080x1440 \
    -o 成片/
```

所有能力在同一条 ffmpeg 命令里完成，**只损失一次画质**——这是它比"剪映里逐步操作"或"分多次转码"强的核心点。

### 5. `report` — 投放台账

```bash
python -m djkit report 成片/ -o 投放台账.xlsx
```

带筛选和冻结窗格的 Excel。前 8 列自动填，后 5 列（投放平台/发布日期/作品链接/状态/备注）留空给你填。重跑会**覆盖**同名文件，填了进度记得先另存。

### 6. `doctor` / `selftest`

`doctor` 查 ffmpeg、libass、依赖（含 AI 三件套是否装了）。

`selftest` 是**带断言的端到端回归**，不是只打日志——跑 16 个阶段、**94 项断言**，失败会返回非零退出码：

```bash
python -m djkit selftest ./_自检          # 默认：解说链用本地桩，不花钱不联网
python -m djkit selftest ./_自检 --live   # 解说链走真实 LLM/TTS
```

覆盖范围：

| 阶段 | 验证什么 |
|---|---|
| scan | 剧名/集数解析 |
| fit | 双规格数量、时长 = 片头+正片/变速+片尾、音轨、封面 12 张 |
| slice | 段数、切片时长（含字幕时间轴平移） |
| report | 台账文件生成 |
| rename | 文件名规范化 |
| assemble | 多段拼接时长 |
| hot | 候选 CSV 行数 |
| 解说链 | 成片规格/音轨/文案/配音，**且成片长度 ≈ 配音长度** |
| 冒烟 | 13 条子命令 `--help` 全部正常 |
| 剧集总纲 | 采样间隔、别名合并、译名替换 |
| 界面 | 规格字符串解析、进度恢复规则、缓存白名单 |
| 文案择优 | 缺段一票否决、六个维度各给理由、`推荐` 徽标唯一 |
| 字幕 / BGM | 文案直接排时间轴（不重新转写）+ **画面上数黄字像素** + **比响度差值** |
| 整季汇总 | 集数 / 画幅 / 时长 / 缺音轨缺封面 / 台账行数 |
| 抽帧 | 每个阶段的产物抽帧留证到 `_自检/帧/` |

离线桩的做法：把 `script.llm_chat` 换成本地固定文案，把 `edge_tts` 模块换成本地假实现（用 ffmpeg 生成等长静音）。这样整条链的编排逻辑都能测，不产生 API 费用。

> 字幕与 BGM 的验证方式值得单说：机器上没装图像识别、也听不了音频，所以改成**可量化的证据**。字幕用纯黑底 + 黄字，抽一帧数 `R>190, G>190, B<100` 的像素——带字幕 4597 px、不带 0 px。BGM 用 `volumedetect` 比 `mean_volume`——纯静音 −91 dB，混入后 −35 dB，差 56 dB。这类断言比「看起来没问题」可靠得多。

## 四、烧字幕（`--burn-sub`）

| 参数 | 说明 |
|---|---|
| `--sub-dir DIR [...]` | 字幕目录，可给多个；默认在素材目录里递归找 |
| `--sub-style` | `default` 白字黑边加粗 / `big` / `small` / `yellow` / `plain` 无描边 |
| `--sub-size N` | 字号像素（相对输出高度），默认 64px@1920 |
| `--sub-font` | 字体名，默认 `Microsoft YaHei` |

**匹配规则**（按顺序，命中即用）：同目录同名 → 同 stem → 剧名+集数 → 宽松包含。跑之前会打印 `字幕匹配 3/20`，一条都配不上会提醒。

**三个已处理的坑：**

- **编码**：国内 SRT 大量是 GBK，libass 只吃 UTF-8。自动识别 UTF-8/UTF-16/GB18030/Big5 并转码。
- **切片后时间轴错位**：把 5–11 秒切出来直接烧整集字幕，画面上会出现第 1 秒的台词。工具读文件名里的 `_p01_5s-11s`，把字幕整体平移 −5 秒并裁到 6 秒内。所以 `slice` 和 `fit` 都能开 `--burn-sub`，顺序随意。
- **字号单位**：libass 的 FontSize 是脚本坐标（PlayResY 默认 288）不是像素，写 `FontSize=20` 在 1920 高画面上会变 133px 巨型字。内部按 `px × 288 / out_h` 换算，`--sub-size 64` 就是字面意义的 64 像素高。

别在 slice 和 fit 两步都开 `--burn-sub`，会烧两遍（字会重影）。

## 五、片头片尾（`--intro` / `--outro`）

```bash
python -m djkit fit 切片/ --intro 品牌片头.mp4 --outro 引导关注.mp4 -o 成片/
```

任意规格、任意帧率、**有没有音轨都行**：自动缩放补黑边、无音轨自动补静音、音视频参数统一后再 concat。规整结果缓存到 `.djkit/overlay/`，批量跑同一片头只处理一次。

## 六、变速（`--speed`）

```bash
python -m djkit fit 切片/ --speed 1.1 -o 成片/     # 加速 10%
python -m djkit fit 切片/ --speed 0.9 -o 成片/     # 放慢
```

- 视频 `setpts=PTS/speed`、音频 `atempo`，**音调不变**（不是鬼畜快进）
- 超出 0.5–2.0 会串联多级 atempo，音质有可闻损失，工具会提醒
- **只作用于正片**，片头片尾保持原速
- **字幕先烧再变速**，文字跟着画面走，不会错位
- 变速后输出仍是设定的 fps（默认 25），1.1x 会丢掉约 9% 的帧——这个幅度肉眼看不出，超过 1.5x 建议实测一下流畅度

## 七、BGM 混音（`--bgm`）

```bash
python -m djkit fit 切片/ --bgm 音乐.mp3 --bgm-vol 0.25 -o 成片/
python -m djkit fit 切片/ --bgm 音乐.mp3 --bgm-vol 0.3 --duck -o 成片/   # 人声出现时自动压低
```

| 参数 | 说明 |
|---|---|
| `--bgm-vol` | BGM 音量 0~1，默认 0.25（原声的重要参考：0.2 隐约听到，0.35 明显抢戏） |
| `--duck` | 闪避：人声出现时自动压低 BGM，人声结束恢复 |
| `--bgm-fade` | 结尾淡出秒数，默认 2，设 0 关闭 |

BGM **自动循环**到成片长度，不管给的是 3 秒还 3 分钟。源素材没有音轨也能混（内部补静音轨，不是补静音输出）。

> 提醒：BGM 得是你有权使用的。平台曲库外的音乐，投放时的版权风险跟画面素材是两回事，但一样会被追。

## 八、封面导出（`--cover`）

```bash
python -m djkit fit 切片/ --cover auto -o 成片/                      # 片头结束 +1 秒
python -m djkit fit 切片/ --cover 3.5 -o 成片/                       # 指定秒数
python -m djkit fit 切片/ --cover auto --cover-sizes 720x1280 -o 成片/  # 额外出小图
```

- 从**成片**里抽帧，所以字幕、BGM 之后的画面所见即所得
- 输出到 `成片/封面/剧名_003.jpg`，质量 `q:v 2`（视觉无损级别）
- `auto` 取「片头时长 + 1 秒」，通常正好是正片第一个有效画面

## 九、多平台规格批量出片（`--specs`）

```bash
python -m djkit fit 切片/ --specs 1080x1920,1080x1440,1920x1080 -o 成片/
python -m djkit fit 切片/ --specs douyin,xiaohongshu -o 成片/
```

| 平台名 | 尺寸 | 说明 |
|---|---|---|
| `douyin` / `kuaishou` / `shipinhao` | 1080×1920 | 竖版 9:16 |
| `xiaohongshu` | 1080×1440 | 竖版 3:4 |
| `bilibili` | 1920×1080 | 横版 16:9 |

- 数字和平台名可混用，重复尺寸自动去重（三个竖版平台写一起只出一个 1080×1920）
- 每个规格输出到 `成片/1080x1920/…`、`成片/1080x1440/…`，单规格时不建子目录（保持兼容）
- **耗时乘以规格数**。跑前会提示总编码次数，100 条 × 3 规格 = 300 次编码，别在赶稿时手滑

## 十、花字 / 标题条（`--title`）

开头那三秒的大字钩子，是推广片最影响完播率的一屏。

```bash
# 所有素材同一句
python -m djkit fit 切片/ --title "他装穷三年 就为这一天" --title-style bar -o 成片/

# 按模板自动生成（每条不同）
python -m djkit fit 切片/ --title-tpl "{剧名} {集}｜一口气看完" -o 成片/

# 手工给每条写标题（CSV：剧名,集数,标题）
python -m djkit fit 切片/ --title-file 标题表.csv --title-style redbar -o 成片/
```

| 参数 | 说明 |
|---|---|
| `--title` | 固定文案，所有素材统一 |
| `--title-tpl` | 模板，可用 `{剧名}` `{集}` `{集数}` `{文件}` |
| `--title-file` | CSV 标题表，按「剧名+集数」匹配；两列时按「剧名,标题」 |
| `--title-style` | `hook` 白字黑边 / `bar` 半透明黑底条 / `yellow` 黄字 / `redbar` 红底白字 |
| `--title-start` | 出现时间（相对正片起点），默认 0.3 秒 |
| `--title-dur` | 持续秒数，默认 3，设 0 则全程 |
| `--title-size` | 字号像素@1920，默认 96 |
| `--title-pos` | `top` / `center` / `bottom` |
| `--title-y` | 自定义纵向位置 0~1，覆盖 `--title-pos` |
| `--title-color` / `--title-border` | 覆盖字色 / 描边像素 |
| `--title-fade` | 淡入淡出秒数，默认 0.3 |

**排版是自动的，但有三条你得知道：**

- **自动换行 + 自动缩字号**：按输出画面 86% 宽度断行，超过 3 行逐级缩小字号。用 Pillow 实测字宽，不是按字数估算，中英混排也准。
- **避免孤字**：末行只剩一两个字时，会从上一行挪字下来（`…这场面太解气` 不会变成 `…这场面太解` / `气`）。
- **想精确控制断行**：在标题里写 `\n`，例如 `--title "第一行\n第二行"`。

**两个实现上的坑（已解决）：**

- **文字不拼进滤镜串**，而是写临时文件用 `textfile=` 传。这样中文标点、英文引号、`%`、`:` 全都不用转义，多行也天然支持。
- **每行单独一条 drawtext**，行距自己算。实测 msyh/simhei 在 drawtext 里的**默认行高是字号的 2.3–2.7 倍**，`line_spacing` 只能在此基础上叠加、压不下去。逐行绘制才能让「文字块高度」和「底条高度」严格对齐——不然通栏底条会只盖住第一行。

## 十一、自动化：配方与目录监听

`fit` 有 34 个参数，天天手敲不现实。把参数固化成一份 YAML，之后一条命令跑完整个流水线：

```bash
python -m djkit run 配方示例.yaml              # 跑一次
python -m djkit run 配方示例.yaml --dry-run     # 只看计划，不动文件
python -m djkit run 配方示例.yaml --watch 120   # 守着目录，来新素材自动处理
```

### 配方长什么样

```yaml
名称: 某剧推广
素材: inbound/某剧            # 必填
输出: outbound/某剧成片
字幕: inbound/某剧/字幕        # 有就烧，没有就跳过

切片:                          # 整段省略 = 不切片，直接拿素材做正片
  模式: head
  时长: 25

花字:
  模板: "{剧名} {集}"          # 或 文字: 固定一句 / 表: 标题表.csv
  样式: bar
  字号: 88

变速: 1.1
BGM: assets/bgm.mp3
BGM音量: 0.25
闪避: true
片头: assets/片头.mp4
片尾: assets/片尾.mp4

规格: [1080x1920, 1080x1440]
封面: auto
台账: outbound/投放台账.xlsx
清理: false                    # true = 出片后删掉中间切片目录
```

跑之前会把计划翻译成人话先打出来：

```
步骤  扫描素材并导出清单 → 切片（head） → 烧字幕 → 加花字 → 变速 1.1x
      → 出封面 → 出 1080x1920、1080x1440 → 生成投放台账
```

### 几个设计要点

- **中英文键名都认**：`素材`/`src`、`输出`/`out`、`BGM`/`bgm` 都行。路径全部相对配方文件所在目录。
- **幂等**：已存在的成片直接跳过。所以放心重复跑，不会重复编码。
- **增量**：新素材丢进 `inbound/`，再跑一次（或开着 `--watch`），只处理新增的那几条。实测已有产物时重跑整条流水线只要 1.9 秒。
- **中间切片放在成片目录外面**（`out/../_切片_成片`），否则会被台账当成成品扫进去。
- **一个文件多个项目**：顶层写成 YAML 列表即可批量跑，互不干扰。
- **`清理: true`** 会删掉中间切片目录——只在确认不再需要重切时开。删之前会打印路径。

### 配合定时任务

`--watch` 适合常驻（开着窗口守目录）。要真正无人值守，用系统定时任务每天跑一次配方即可：

- Windows 任务计划程序：`djkit.cmd run D:\推广\配方.yaml`
- macOS/Linux：`crontab -e` 加 `0 9 * * * cd /path && python -m djkit run 配方.yaml`

**哪些环节仍然必须人工**：素材下载（平台有登录态和频率限制，自动化拉取违反用户协议）、授权核对、投放发布。工具能做的是「素材落地到成片入库」这一段全程无人。

### 解说模式：一条配方从长篇直接出解说成片

配方里写 `模式: 解说`，走的是另一条流水线：

```
高光检测 → 只转写选中片段 → LLM 写文案 → TTS 配音 → 拼接出片（画面按配音长度自动裁）
```

```yaml
模式: 解说
素材: ../素材/某剧            # 单文件或整季目录
输出: out/解说
解说:
  段数: 6
  段长: 8
  语言: en
  字幕模型: small.en
  解说时长: 26
  背景: "剧名…人物关系…前情…"     # 决定文案质量的关键
  音色: zh-CN-YunjianNeural
  原声音量: 0.12
规格: [1080x1920]
花字: {模板: "{剧名} {集}", 样式: bar}
封面: auto
```

完整模板见 `配方示例_解说.yaml`。

**幂等与重跑**（这条链会调 LLM 和 TTS，是真花钱的）：

- 成片已存在 → 整集跳过。实测重跑 **1.3 秒**返回。
- 中间产物（片段清单、转写、文案、配音）按内容签名缓存在 `_工作/<剧集>/`，签名包含源文件 mtime、段数、背景、时长等。**改了哪一项就只重算哪一项**，删掉一档成片重跑只补那一档（实测 11 秒，不重新调用 LLM/TTS）。
- 要强制全部重做：配方里写 `解说: {重跑: true}`。
- ASR / LLM / TTS 都带 2 次重试 + 退避，网络抖一下不会让整集报废。
- 跑完自动出 `_投放台账.xlsx`（多规格时扫第一档，避免同一集重复三行）。

**音画对位（`按段: true`，默认开）**

原来的做法是「一条连续旁白铺在一串画面上」——文案是一篇通顺的旁白，画面按时间排，
两者没有映射，所以中段必然漂。实测过：解说在讲「马特」，画面字幕是「本还活着」，差一个片段。

现在是**每一段画面单独写 1~2 句、单独配音**，该段画面长度 = 这段配音长度：

```
第 k 段画面 → 只写第 k 段的台词内容 → 单独 TTS → 画面长 = 配音长 + 0.35s
```

这样「说到哪、画面是哪」由数据结构保证，不靠模型自觉。现有 `assemble` 一行没改——
把各段音频按顺序拼成一条（每段补静音到画面长度），它仍然只认「一条配音 + 一串带时长的片段」。

要退回旧方案写 `按段: false`。

**界面里也是逐段的**：文案页不再是「一大段文本」，而是每段一个编辑框，标题显示
「第 3 段 · 41 字 · 约 10.0s」。整段说完才切画面，所以句数直接决定这一段多长。

注意时长关系变了：**成片长度 = 各段配音长度之和**，不再是「解说时长」这个参数说了算。
段长（默认 12s）是每段的上限，段数 × 段长就是理论最长。
目标 40 秒但只出了 34 秒，说明该加段数（5–6 段），不是改时长参数。

**三个设计决定，都是踩出来的：**

1. **高光检测必须用 VAD 门控**。`hot` 挑的是「声音大 + 画面动」，而影视里声大画面动的往往是爆炸、打斗、配乐——**恰好没有台词**。实测直接拿候选去转写，5 段里一句词都没有。现在先用 VAD 扫出语音区间，把无语音位置的分数压到 2%，候选才落在有对话的地方。

2. **只转写选中片段**，不转整集。42 分钟全量转写要几分钟，而文案只需要屏幕上这几段说了什么。把片段音轨拼成一条再转写，35 秒音频 4 秒转完（8.8x 实时）。

3. **画面跟着配音走**。配音 20 秒却配 35 秒画面，后面十几秒无声放片，观众直接划走。出片前按配音时长从尾部裁画面（配音比画面长则由 `assemble` 自动延长末段）。

跑完之后建议看一眼 `_工作/<剧名>/文案/文案_A.txt`——LLM 偶会轻微加戏（实测出现过台词里没有的"箱子"），这是文案环节唯一需要人工的地方。

## 十二、多段拼接（`assemble`）

影视解说号和盘点号的基础能力：把一个片段清单按顺序拼成一条成片。片段可以来自**不同源文件**，每段独立指定起点、长度、段内标签。

```bash
python -m djkit assemble 清单示例.yaml
python -m djkit assemble 清单.csv -o out/合集.mp4     # CSV 简版
```

```yaml
输出: out/盘点_十部反转到最后.mp4
规格: 1080x1920
缩放: blur
花字: {文字: "十部反转到最后", 时长: 2.5}    # 全局片名，贴顶部
片段:
  - 源: 某电影.mp4
    起: "0:12:34"          # 90 / 1:30 / 00:01:30.5 都认
    长: 8
    花字: "第一部 反转在这"  # 段内标签，自动让到底部
  - 源: 某剧_第03集.mp4
    起: "02:10"
    长: 10
```

CSV 简版（适合批量生成清单）：`源,起,长,花字`

**几个设计细节：**

- **段内标签自动避开全局花字**：有全局片名时，段内标签默认落到底部。横屏转竖屏时上下都是模糊边，文字放这儿不压画面主体。
- **无音轨的素材自动补静音**，所以「电影（有线声）+ 剧集（无声）」混拼不会错位。
- **段内字幕会自动平移**：给某段指定整集 SRT，工具按该段起点裁取，不会出现前一段的台词。
- **BGM 在拼完之后铺整条**，不是逐段铺，所以不会有接缝。
- 不写 `长` 就表示从起点到结尾（适合拿某段之后全部）。

**这条命令能做什么、不能做什么：**

| 能做 | 不能做 |
|---|---|
| 按时间码精确取段、跨片拼接 | 自动判断哪一段好看（需人工给时间码） |
| 每段独立花字、字幕 | 生成解说文案 |
| 横屏转竖屏、统一规格 | 配音（TTS） |
| BGM + 闪避 | 音画自动对位（解说词和画面的节奏匹配） |

解说号的完整链路是「找片段 → 写稿 → 配音 → 对位 → 拼接」，`assemble` 覆盖了首尾两步，中间三步要接外部工具（ASR 转写、LLM 写稿、TTS 配音）。

## 十三、AI 三件套：找片段 / 转写 / 配音

解说号的完整链路是「找片段 → 转写 → 写稿 → 配音 → 拼接」。工具覆盖其中四步，写稿留给人和 LLM。

### 1. `hot` — 自动找高光片段

```bash
python -m djkit hot 某剧_S01E01.mp4 --top 6 --len 8
python -m djkit hot 素材库/ --top 4 -o 候选.csv    # 整个目录
```

**原理**：两路信号加权，全离线。

| 信号 | 怎么算 | 权重 |
|---|---|---|
| 音频能量 | 解成 8kHz 单声道，按 0.5 秒算 RMS，取分位排名 | 0.68 |
| 画面变化 | **只解 I 帧**（`-skip_frame nokey`），缩到 64×36 灰度算帧差 | 0.32 |

**速度**：42 分钟 1080P 素材，**17 秒**分析完。为什么不逐帧解——42 分钟全解码要 8-15 分钟，只解关键帧快 30 倍，代价是画面变化的时间精度只有 1-2 秒，对找高光够用。

**间隔自适应**：默认按 `时长/取段数×1.2` 自动拉大最小间隔（42 分钟取 6 段 → 180 秒）。手动设小会挑出同一场戏的连续切点，对合集来说是重复不是多样性。

输出 `源,起,长,花字,分数` 的 CSV，**可以直接喂给 `assemble`**。

> **局限要说清楚**：分数只代表「声音大 + 画面动得多」。短剧和电影里大量爽点是静场表演——一个眼神、一个下跪、一句压低声音的话，音频检测抓不到。这个工具的作用是把 42 分钟缩成 6 个候选让你挑，不是替你决定。

### 2. `asr` — 语音转写生成字幕

```bash
python -m djkit asr 某剧_S01E01.mp4 --lang en --model small.en
```

输出三份：`.srt`（字幕）、`.txt`（带时间码的纯文本，写文案时最有用）、`.json`（程序用）。

| 参数 | 说明 |
|---|---|
| `--model` | `tiny` / `base` / `small` / `medium` / `large-v3`，可加 `.en` 后缀。英文对白 `small.en` 性价比最高 |
| `--lang` | `en` / `zh` / 留空自动检测 |
| `--device` / `--compute` | `cpu`+`int8` 默认；有 N 卡可 `cuda`+`float16` |

**三个国内环境的坑（都已处理）：**

1. **模型下载**：默认走 `HF_ENDPOINT=https://hf-mirror.com`，直连 huggingface 基本不通。
2. **hf_xet 401**：新版传输协议会直连 `cas-server.xethub.hf.co`，走镜像必然 401。已默认设 `HF_HUB_DISABLE_XET=1`。
3. **模型文件落不下来**：huggingface 默认用符号链接组织 snapshots，Windows 上非管理员链不出来，结果 blobs 有 141MB 而 snapshot 目录是空的。改成 `snapshot_download(local_dir=...)` 落实体文件。

另外**绕开了 PyAV**：faster-whisper 内部用 `av.open(metadata_errors=...)`，而 av 19.0.2 不认这个参数。现在自己用 ffmpeg 解成 16k 数组直接喂给模型，少一层依赖也更快。

模型缓存在 `~/.cache/djkit/models/`，第二次不再下载。

### 3. `script` — 台词转解说文案（LLM）

```bash
python -m djkit script E01.srt.txt --seconds 24 --variants 3 \
    --context "外星人入侵六个月后，汤姆是历史老师，小儿子被抓走…"
```

输出 `文案/文案_A.txt`、`_B`、`_C` 三个版本（三个不同开场角度，避免同质化）。

| 参数 | 说明 |
|---|---|
| `--seconds` | 目标解说时长，按 4.1 字/秒换算成字数区间 |
| `--variants N` | 生成 N 版，分别用「悬念 / 人物处境 / 反常识判断」开场 |
| `--context` | **背景设定，最影响质量的一个参数**：剧名、人物关系、前情 |
| `--start` / `--end` | 只取某段台词，如 `--start 36:40 --end 38:00` |
| `--style` | 风格描述，默认「克制的叙述，不煽情，偶尔一句冷判断」 |

**配置**（写到 `~/.djkit/llm.yaml`，不要提交到仓库）：

```yaml
base_url: http://你的接口/v1
api_key: sk-xxxx
model: qwen3_6
```

也可以用环境变量 `DJKIT_LLM_BASE` / `DJKIT_LLM_KEY` / `DJKIT_LLM_MODEL` 覆盖。

**两个实现要点：**

- **关掉思考模式**。qwen3 这类推理模型默认会先长篇思考，约束一多就在 `reasoning_content` 里反复复述要求、把 `max_tokens` 耗光，正文一个字都不出。加 `chat_template_kwargs: {enable_thinking: false}`，不认的服务返回 400 会自动回退重试。
- **字数必须硬性约束**。只说「约 103 字」模型会写 50 字。要写「必须写满 5–9 行，总字数 87–118 字」，并给出每行 10–18 字。

> 实测：不给 `--context` 时文案会空泛（因为台词本身就那几句）；给了人物关系和前情，8 行 102 字，念出来 23.7 秒，和目标 24 秒几乎重合。

### 4. `tts` — 文案转配音

```bash
python -m djkit tts 文案.txt --voice zh-CN-YunjianNeural --rate "+2%"
```

走 edge-tts（微软语音），**不需要 API key**，输出 mp3。

| 音色 | 特点 |
|---|---|
| `zh-CN-YunxiNeural` | 男声，年轻，通用解说 |
| `zh-CN-YunjianNeural` | 男声，低沉有力，适合悬疑/末世/硬核 |
| `zh-CN-XiaoxiaoNeural` | 女声，亲和 |
| `zh-CN-XiaoyiNeural` | 女声，活泼 |

会自动清掉文案里的 markdown 强调符（`**` 会被念成"星号星号"）和时间码前缀，可以直接把 `asr` 生成的 `.txt` 丢进去。

### 5. 解说片怎么拼

`assemble` 的清单里加两行就能出解说版：

```yaml
输出: out/解说.mp4
配音: 配音.mp3
原声音量: 0.12        # 原声让路，默认给了配音就自动压到 0.12
花字: {文字: "他只想把儿子带回来", 时长: 2.5}
片段:
  - {源: 某剧.mp4, 起: "36:44", 长: 8, 花字: "我儿子还活着"}
  - {源: 某剧.mp4, 起: "36:53", 长: 8}
```

混音层级：**配音（满）> 原声（0.12）> BGM（0.2 且被人声闪避）**。配音比画面长时会在尾部截断并警告。

#### 解说片的字幕：直接按文案排，不走 ASR

这是本项目里最省事的一个判断。解说片的字幕内容**你本来就有**——文案在手里，每段的画面时长也在手里，那就没必要「先念一遍再听回来」。

```yaml
字幕: auto          # 出片时按文案自动生成
字幕样式: default    # default / big / small / yellow / plain
```

生成逻辑在 `subtitle.py`：

- **时间按字数分配**，不按段平均分。字多的句子本来就念得久，平均分会导致字幕跑在语音前面。
- 折行按 16 个汉字一行、最多两行，**优先在标点处断开**，断不开才硬切。libass 不会自动换行，这步必须自己做。
- 太短的条目（< 0.55 秒）并进上一条，否则一闪而过反而看不清。
- 写出的 SRT 条目间必须有空行、末尾必须有空行。少一个 libass 就直接打不开文件，不报错，只是不出字幕——这个坑踩过一次。

比 ASR 好在三点：**专名一个都不会错**（`汤姆` 不会被听成 `汤母`）、**不用等转写**、**时间轴天然对齐**（时间是从文案和时长算出来的，不是猜的）。

烧制顺序是**花字先、字幕后**：花字在画面上方、字幕在下方，两者叠不冲突。花字只出现几秒，字幕贯穿全片。

#### 观察路径：`assemble` 的字幕有两种

| 配置项 | 时间轴基准 | 用在哪 |
|---|---|---|
| `片段[].字幕` | 该片段在成片里的起点 | 老素材切片（字幕文件是整集的，要平移） |
| `字幕`（顶层） | 整条成片 | 解说片（SRT 是按文案现生成的，天生对齐） |

顶层 `字幕` 是拼完再烧，所以时间码不用做任何平移。

### 完整流程

```bash
python -m djkit hot    E01.mp4 --top 6                      # 1. 找候选
python -m djkit asr    E01.mp4 --lang en --model small.en    # 2. 转写
python -m djkit script E01.txt --seconds 24 --variants 3 \
        --context "人物关系与前情"                            # 3. 写文案
python -m djkit tts    文案/文案_A.txt --voice zh-CN-YunjianNeural  # 4. 配音
python -m djkit assemble 解说.yaml                          # 5. 拼接出片
```

## 十四、先说清楚三版文案怎么选（`score.py`）

`script --variants 3` 会生成 A/B/C 三版，选题角度分别是「悬念开场 / 人物处境 / 反常识判断」。接下来要选一版出片——选错了，配音白做、画面白拼，还得重来一遍。

原来的选法是「字数最接近目标的那一版」。这个标准不够，因为：

- **字数对得上，但少写了一段**。三段的画面只配了两段词，剩下一段 8 秒全是画面没说话。
- **字数对得上，但全是 7 字短句**。念出来像念标签，不像解说。
- **字数对得上，但两句完全重复**。模型在小红书腔和正经叙述之间摇摆时会干这事。
- **字数对得上，但混进了「本期视频」「接下来我们看看」**。这类词直接出戏。

所以现在用**六个维度加权打分**，每一维都给 0–100 和一句人话理由：

| 维度 | 权重 | 怎么算 |
|---|---|---|
| 覆盖 | 0.30 | 有词的段数 / 总段数。**缺段不是线性扣分**：比率 ×100 只在写满时给，否则砍到 ×40 |
| 字数 | 0.24 | 偏差 0 → 100；偏差 30% → 40；≥50% → 0 |
| 句长 | 0.14 | 落在 8–24 字的句子占比 |
| 重复 | 0.14 | 去标点后逐句比，重复率 ≥30% → 0 |
| 出戏词 | 0.06 | 命中「本期/这期/视频/大家好/点赞关注」等 → 每个扣 1/3 |
| 可念 | 0.12 | 含英文长词、markdown 残渣的句子占比，超 25% → 0 |

**覆盖权重大且非线性**，因为缺一段是结构性问题——那一段画面就是废的，字写得再漂亮也补不回来。这是「一票否决」的软实现：不直接判死，但 0.30 的权重乘上 ×40 的惩罚，缺一段基本赢不了。

**分数是相对的**。三版之间比，不做绝对好坏判断。全都很差时仍然要选一个（用最好的），但会显式提示「几版分数接近，建议并排看一眼」。

**界面怎么用这套分数**：

- A/B/C 标签上直接显示总分，推荐的那版高亮、加 `推荐` 徽标。徽标**全局只有一个**（由 `best` 决定，不由分数档位决定）——早先的 bug 是三版分数打平时三个标签都被标「推荐」。
- 分数档位叫「扎实 / 可用 / 凑合」，**不带「推荐」二字**，避免和徽标混淆。
- 标签下面有一排评分明细：三列并排，每列六个维度一根条（绿/黄/红），右边是分数，鼠标悬停看细节，最下面一行是扣分理由。点哪列就切到那版。
- 只有一版时整块隐藏，不占地方。

**为什么不调模型来评**：本地打分不花钱、不联网、毫秒级、结果稳定。而且择优标准是几条明确规则，规则能写成代码就不该烧 token。真要看文采，人看「并排看」那三列比任何模型打分都准。

**为什么理由要说人话**：`句长：2 句偏短（均值 7 字）` 比 `line_len=0.62` 有用得多。用户看到「缺 1 段（那几段画面会没词）」会立刻去补，看到 `coverage=0.4` 只会关掉界面。

## 十七、剧集总纲（`series`）

做整季解说时，每集都独立生成会出三个问题：**第 8 集还在重新介绍主角**、**10 条视频互不相干**、
**同一个人每集叫不同的名字**。总纲就是一次性把整季读一遍，攒出一份可复用的剧集记忆。

```bash
# 整季目录（15 集，约 20 分钟）
python -m djkit series "D://素材//某剧 S01" --model small.en --lang en

# 先拿 2 集试水
python -m djkit series "D://素材//某剧 S01" --eps 2

# 调提示词后只重汇总，不重转写
python -m djkit series "D://素材//某剧 S01" --remix
```

产出两个文件，都在素材目录下：

| 文件 | 给谁 | 说明 |
|---|---|---|
| `总纲.md` | **人** | 主线 / 人物 / 名词 / 译名表 / 分集一句话 / **存疑** |
| `总纲.json` | 程序 | 分集摘要原始数据，带签名缓存 |

### 五步流水线

```
每集采样 7 分钟音频 → 转写
        ↓
从全季台词抽一张「译名表」（同一人只能有一个中文名）
        ↓
专名校正：把 ASR 听错的名字改回来（Sanjo → Shenzhou），手工表在这里覆盖
        ↓
逐集摘要：只把「本集台词里出现过」的术语给它（按出场裁剪）
          同时让它回填本集新出现、表里还没有的名字
        ↓
译名表收尾：把被拆开的「名 / 姓 / 全称」合并成一条
        ↓
汇总：主线 + 人物表 + 名词表
```

**译名表那一步是踩出来的。** 没有它时，同一部剧的主角第一集叫「迈克尔·伯纳姆」、
第二集叫「米歇尔·伯恩汉姆」，主线段落里两种叫法混着用。

**「按出场裁剪」也是踩出来的，而且是更隐蔽的一类错。** 全季译名表里写着
「洛卡＝发现号舰长」，第一集台词里根本没有这个人，摘要却写成
「洛卡擅自下令开火」——实测 E01 台词 **0 次**提到 Lorca。模型看到「Captain」
就从表里挑了个舰长填进去。现在只给本集出场过的术语，E01 正确地写成「舰长下令开火」。

**「译名表收尾」解决的是另一类同名分裂**：后期补进来的「菲利帕」和「乔治乌」
各自独立，代码没法判断是不是同一个人（也可能真是两个），只能让模型再看一遍。
拿不准的它会保留两条——**这比硬并成一个人安全**。

### 专名校正：唯一允许"外部知识"的一步

前面所有步骤都写着「只收台词里出现过的，不要引入外部知识」。这一步是唯一的例外，
因为 ASR 对科幻/奇幻专名的错误率实在太高（实测 small.en 把 `Shenzhou` 听成 `Sanjo`、
`T'Kuvma` 听成 `Takuvma`、`Sarek` 听成 `Zarek`），而每个错名都会跟着流进每一集的文案。

做法是**只让模型出补丁，不让它复述整张表**：

```json
{"校正":[{"原名":"Sanjo","正确":"Shenzhou","理由":"主角服役舰"}],
 "合并":[{"保留":"Georgiou","并入":["Philippa"],
          "全名":"Philippa Georgiou","译名":"菲利帕·乔治乌","理由":"同一人"}]}
```

补丁在本地应用（`apply_name_fixes`），所以：被并掉的条目**原名会留进别名**、一条不丢；
改动逐条记下来写进 `总纲.md` 的「已自动校正的专名」一节，对不上就改回去。

设计上卡了两条边界：

- **不让它复述整张表。** 104 条的表让模型全吐出来，实测 2000 token 就截断，JSON 直接坏掉
  （`Expecting ',' delimiter`）。改成补丁后输出只有几百字，稳定。
- **「绝不新增台词里没出现过的人物」。** 这一步只校正拼写和合并，不是补人物表。
  越界了就会变成"模型凭记忆编人物"，那比 ASR 错字更糟。

**手工兜底：`--names`。** 模型改不动的时候，人一次性钉死：

```bash
djkit series 剧集目录 --names "Michael Burnham=迈克尔·伯纳姆, USS Shenzhou=神舟号"
```

中英文逗号、冒号都认（`原名：译名` 也行）。优先级最高——它是在自动校正**之后**应用的，
所以模型不会把用户刚钉死的名字又"纠正"回去。

不想让模型碰名字就加 `--no-fix`，只走手工表。

### 为什么不全量转写

| | 转写量 | 耗时（实测 4.6~7.2x 实时） |
|---|---|---|
| 全季 15 集全量 | 约 600 分钟 | **约 100 分钟** |
| 每集采样 7 分钟 | 105 分钟 | **约 20 分钟** |

总纲要的是主线，不是每句台词。采样均匀分布在正片里，跳过开头 100 秒（片头 + 前情回顾，
不跳会把上一集剧情混进来）和末尾 60 秒（片尾字幕）。

### 怎么接到出片

配方里写一行就够，默认就是开的：

```yaml
解说:
  总纲: 自动        # 自动找 素材目录 / 上一级 / 输出目录 下的 总纲.md
# 总纲: 关         # 不用
# 总纲: 路径.md    # 指定
```

注入时做两层裁剪：

- **按集**：做第 5 集只带第 5 集及之前的剧情，不会把结局漏进提示词（不然会剧透）
- **按节**：主线 1100 字 / 人物 700 / 名词 450，各自限额。整篇截断在 15 集时
  会把人物和名词整个切掉，而那恰恰最影响文案

**总纲是整季视角，不是本集事实。** 这一点必须写进提示词，否则会出新错：
总纲说「洛卡是发现号舰长」，第一集的文案就写成了「舰长洛卡」——
而第一集的舰长其实是乔治乌。现在注入的开头会明确说：
台词只说「舰长」而没给名字时，就写职务，不要从人物表里挑名字。

### 三个必须知道的限制

1. **总纲会错，而且错得很自信。** 采样只有 7 分钟/集，ASR 还有错词（实测把 `Shenzhou`
   听成 `Sanjo`、把 `T'Kuvma` 听成 `Takuvma`）。专名校正能修掉一部分，
   剩下的靠 `--names` 手工钉死；每一处拿不准的东西还会放进 `## 存疑` 一节，
   而不是混进主线——**那一节就是给你核对用的**。
2. **改过的 `总纲.md` 不会被覆盖。** 程序记了 md 的哈希，发现人工改过就保留你的版本
   （要强制覆盖加 `--force`）。提示词指纹只影响缓存，不影响人工改动的判断。
3. **总纲写错一个设定，后面每一集都跟着错。** 这是它唯一的风险，也是必须先看一遍的原因。
4. **人物关系会编。** 采样只有 7 分钟/集，模型看到「被关起来」就往「囚犯」上写——
   实测把神舟号舰长菲利帕·乔治乌写成了「克林贡囚犯」。现在提示词里卡了
   「只能写分集记录里明确写到的关系，看不出来就留空」，好多了，但仍然隔着一层 ASR。
   **人物表当参考，别当事实**；写到某一集的具体剧情时，还是以那一集的台词为准。

## 十八、桌面客户端（`app`）

```bash
python -m djkit app            # 开窗口
python -m djkit app --debug    # 开窗口 + devtools（F12 可查前端）
```

日常用**双击 `启动客户端.bat`**。它会用 `pythonw` 拉起窗口（控制台只闪一下）。

排查用：`启动客户端.bat --check` 只打印它选中的 pythonw 和项目目录，不启动。

### 它是什么

**pywebview 外壳 + 本地 HTTP 服务**，界面仍然是那套 HTML/CSS：

```
┌─ 系统 WebView2 窗口（pywebview 只负责开窗）──────────┐
│  index.html / app.js / style.css                    │
│        │  HTTP（127.0.0.1:随机端口）                 │
│        ▼                                            │
│  ThreadingHTTPServer（标准库）                       │
│    ├── /video  支持 Range，能拖进度条                │
│    ├── /thumb  按需抽帧并缓存                        │
│    └── /api/*  长任务进单工作线程，前端轮询           │
└─────────────────────────────────────────────────────┘
```

**为什么不直接让 pywebview 加载本地页面**：实测 WebView2 会把 `<video src="file://…">`
判成 `media error 4`（源不受支持），直接用 `html=` 注入的页面还是「不透明源」，连读文件都不允许。
所以坚持两层：壳只开窗，页面和视频全部走 `http://127.0.0.1:<port>`。

白送的好处：**服务出问题时，在浏览器里打开同一个地址照样能用**。

### 比浏览器版多什么

| | 客户端（`app`） | 网页版（`gui`） |
|---|---|---|
| 启动 | 双击 `启动客户端.bat` | 跑命令再开浏览器 |
| 窗口 | 原生窗口，有任务栏图标，可最小化 | 浏览器标签页 |
| 选文件 | **原生文件选择框**（「选择…」按钮） | 只能粘贴路径 |
| 界面文字 | 不可选中（像应用） | 可选中（像网页） |
| 依赖 | pywebview（约 5MB，用系统 WebView2） | 无额外依赖 |

**不打包浏览器内核**：pywebview 用的是系统 Edge WebView2（Win11 自带，Win10 需装运行时）。
装完 5MB，不是 Electron 那种 100MB+。

**启动时自动清页面缓存。** `gui_out/_webview` 是 WebView2 自己的数据目录，长期用会攒到 100MB+。
它只能在开窗前清（窗口一开文件全被锁死），所以 `app.trim_webview_cache()` 在
`create_window` 之前跑：超过 150MB 才动，只删 `Cache` / `Code Cache` / `GPUCache` / `DawnCache`
这几个纯缓存目录，不动 Local Storage —— 那里可能有偏好设置。

### 这里踩过的坑（都已处理）

1. **窗口对象不能挂在 Api 上。** 挂在 `self.window` 会被 JS 桥递归遍历，
   日志刷屏 `window.native.ActiveForm.ModifierKeys.A.A.A…: maximum recursion depth exceeded`，
   桥接直接哑掉。改成模块级 `_WIN`。
2. **关窗必须结束进程。** `window.events.closed` 里 `os._exit(0)`：WebView2 的子进程
   不保证跟着退，反复开关几次就会出现「桥接再也不就绪」。
3. **不让文件拖拽导航。** WebView2 默认会把拖入的文件当导航目标，页面白屏且回不来。
   现在 `dragover`/`drop` 全部 `preventDefault`。
4. **单实例。** 占一个本地端口当互斥锁，第二次双击直接退出——否则两个窗口抢同一份状态。
5. **开窗不白闪。** `background_color` 设成页面底色（`#14161a`）。

6. **pythonw 没有 stdout。** 双击启动时 `sys.stdout` 是 `None`，任何 `print` 都会抛
   `AttributeError: 'NoneType' object has no attribute 'write'`，进程瞬间消失、什么提示都没有。
   现在检测到 `sys.stdout is None` 就把输出接到 `gui_out/app.log`，并在文件头写一行启动时间。
   **双击没反应时，先看这个日志。**
7. **子进程不能弹控制台。** `pythonw` 自己没有控制台，这时再拉 ffmpeg 这类控制台程序，
   Windows 会**给它分配一个新控制台窗口**——表现就是每点一步就弹一个黑框（内容全空，
   因为 stdout 被我们 capture 了）。统一在 `core.child_kwargs()` 里加
   `CREATE_NO_WINDOW`（0x08000000），`core.run` / `hot.py` / `selftest.py` 三处子进程调用都走它。
8. **启动脚本必须 CRLF。** `.bat` / `.vbs` 用 LF 换行会被 Windows 解析成一整行，
   报「未结束的字符串常量」。写文件时统一转成 CRLF，并且保持纯 ASCII，避开代码页问题。

> 上一轮评估里我写过「WebView2 会残留 12 个进程」，这次实测**没有留下任何孤儿进程**
> （12 个都有活着的父进程，属于别的程序）。当时的判断不成立。

## 十九、图形界面（`gui`）

```bash
python -m djkit gui --no-browser # 只起服务，自己用浏览器访问
```

浏览器打开 `http://127.0.0.1:8770/`，四步走完：**素材 → 片段 → 文案 → 出片**。

**界面做了什么**（命令行没有的）：

| 环节 | 命令行 | 界面 |
|---|---|---|
| 剧集总纲 | `djkit series 目录` | 素材页下方「剧集总纲」块，一键生成，状态栏显示 `✓ 14 人 · 16 名词 · 104 译名`；带「手工译名」输入框 |

| BGM | `--bgm --bgm-vol --duck` | 右侧参数区「BGM」块：原生选文件 + 音量滑块 + 闪避开关 |
| 进度 | 等终端刷屏 | 进度条 + 滚动日志 |
| 成片 | 去目录里找 | 直接内嵌播放；多画幅出片时点规格切换 |
| 整季成片 | 自己翻目录 | 第 4 步下方「整季汇总」：缩略图墙 + 一屏统计 |

**架构**（都是为了少依赖、好排错）：

```
浏览器 ──HTTP──> ThreadingHTTPServer（标准库）
                    ├── 静态页（index.html / app.js / style.css）
                    ├── /video   支持 Range，能拖进度条
                    ├── /thumb   按需生成缩略图并缓存
                    └── /api/*   长任务丢进单工作线程，前端每 0.8 秒轮询状态
```

- **不用 FastAPI/Flask**：标准库够用，少一层依赖；也不用 SSE，轮询断线更皮实。
- **单工作线程**：同一时间只跑一个任务，避免 ffmpeg 和模型并发抢资源。
- **只监听 127.0.0.1**：天然只给本机用。
- 产物落在 `gui_out/`，中间文件在 `gui_out/_work/`。
- **总纲写到 `gui_out/总纲.md`**（素材盘保持只读）。生成一次后，后面每一集的文案自动带上；
  素材页那块的「只重汇总」按钮对应 `series --remix`，调完设定重跑只要 1 分钟。
- **任务可取消**：`/api/cancel` 置一个 `threading.Event`，各任务在步骤边界 `check_cancel()`。
  取消只在步骤之间生效——ffmpeg 一旦开始就得等它跑完，所以文案是「等当前步骤结束」。
  `run_explainer` / `series.build` 也接受 `should_stop`，在集与集之间退出。
- **`reset` 在忙时返回 409**：原来它直接 `STATE.update({"busy": False})`，
  下一次 `run_task` 就能再起一个线程，两个任务并行写同一份 STATE。现在忙时拒绝，前端也禁用按钮。
- **整季批量**：素材页有「整季批量」块，选目录后按当前参数把每一集全自动跑一遍。
  内部直接复用 `run_explainer`（配方那条链路），所以**封面、台账、多规格都是白送的**；
  进度从日志里的 `[3/15]` 反推。产物在 `gui_out/整季/`。
- **单集出片也出封面和台账**：`extract_cover` 抽一帧做首图（`/cover` 端点回显），
  `cmd_report` 追加到 `gui_out/_投放台账.xlsx`。台账失败只记日志，不判定成片失败。
- **首次转写会提示下载模型**：检查 `~/.cache/djkit/models/faster-whisper-<model>`，
  没有就在日志里说明体积和耗时，避免界面看起来卡死。
- **「换一批片段」**：把当前所有起点回传给 `/api/analyze` 的 `avoid`，
  后端在选段时跳过这些位置（`pick_highlights(avoid=...)`），得到下一个批次。
  不这么做的话，参数不变时算法是确定性的，重新分析只会得到一模一样的结果。
- **勾选不会被轮询翻回去**：前端把未确认的勾选记在 `selLocal`，轮询合并时用它压住服务端旧值，
  等服务端确认（`/api/segments` 返回）后再交回。否则保存有 200ms 防抖、
  轮询每 0.8 秒一次，中间任何一次都会把刚点的结果覆盖掉。
- **跳步只在阶段变化时发生**：`stage` 会长时间停在 `segments`，
  原来写的「stage 是 segments 且在第 1 步就跳」会导致回到素材页立刻被弹回，
  想改参数重新生成根本回不去。
- **三版文案一次写透，A/B/C 切着挑**：`/api/script` 跑满 3 次，分别用「悬念开场 / 人物处境 / 反常识判断」
  三种角度，全部留在 `STATE["variants"]` 里。默认选哪版由 `score.py` 的**六维加权打分**决定
  （缺段一票否决，详见第十四章）——以前是「留最长的一版」，结果常常是超时的那一版；
  后来改成「字数最接近」，又会在少写一段时选错。
  界面上点 A/B/C 切换，**每版改过的内容各自记着**（前端的 `varEdits`），切走切回来不会丢，也不会污染另外两版。
  某一版有段落没写出来会在标签上标「缺段」，出片前必须补齐（少一段就少一段画面）。
  标签上有总分，下面一排是三列评分明细（每维一根条 + 分数 + 理由），点列切版。
  旁边还有「并排看」：三列只读视图，点哪列切哪版——三版的差别全在开头几句，并排一放就看出来了。
- **字幕和 BGM 在界面上就能开**：`task_render` / `task_batch` 都接了
  `burn_sub / sub_style / bgm / bgm_vol / duck`。字幕默认开（`default` 样式），
  内容按文案现排——界面里生成的字幕和命令行 `--burn-sub` 不是一回事，前者不读外部 SRT。
  **BGM 路径必须先 `resolve()`**：`assemble` 的相对路径基准是工作目录 `_work/`，
  直接把用户输入的 `音乐.mp3` 塞进配置，ffmpeg 会去 `_work/音乐.mp3` 找，然后报文件不存在。
  完成消息里会写「带字幕 yellow、BGM 0.2」，省得回头确认到底开没开。
- **整季汇总页**：第 4 步下方一屏看清这一季出了什么——每集一张卡（缩略图、集号、时长、画幅、文案字数），
  缺音轨 / 缺封面的标红，汇总行是「N 集 · 总时长 · 总体积 · 画幅」。
  后端 `season.py` 只读不写，扫 `gui_out/整季/` 下的画幅目录；`/api/season` 按
  「目录 mtime + mp4 数量 + 画幅」缓存，前端只在「跑完批量 / 进成片页 / 启动探一次」三个时机拉，
  **不跟着 0.8 秒轮询扫盘**。
  汇总行不信后端的 `problems` 字段，自己从 episodes 数一遍——后端只报「有没有」，前端要报「几集」。
  封面路径由后端给 `cover_path`，**前端不拿 `.mp4` 去 `replace` 猜**——成片是 `.mov` 时就会猜错，这是改之前真实存在的问题。
  `/cover?p=` 加了 `is_relative_to(OUT_ROOT)` 校验，越权直接 403（实测拦住了 `C:/Windows/win.ini`）。
  目录不存在时 `scan_season` 也把 11 个字段给全（`specs` 为空数组、`total_mb` 为 0），
  前端不用每处判空——少给一个键就是 `undefined`，靠前端兜太脆。
- **总纲那块的「手工译名」输入框**：对应命令行的 `--names`，逗号分隔写「原名=译名」。
  ASR 把主角名字听错时，这是最省事的一手——改完点「只重汇总」，1 分钟就把整季称呼统一了。
- **关窗不丢进度**：片段、三版文案、勾选、成片信息落在 `gui_out/_last.json`（临时文件 + 原子替换，
  写一半断电不会留下半个 JSON）。重开窗口自动恢复，不用重新分析那 30 多秒。三条保护：
  素材文件不在了只提示不恢复；`rendering` 这类中间态不恢复（否则重开就是一个卡住的界面）；
  成片被手工删了自动退回文案页。点「重置」会删掉这个文件。
- **单集多规格，配音只做一次**：画幅改成多选，配音和音频对齐只跑一遍，之后按每个画幅重编码。
  第一个画幅沿用 `xxx_解说.mp4`，后面的加 `_1920x1080` 后缀。成片页列出所有规格，点谁播谁
  （`/video?p=`，只允许输出目录里的文件）。某个规格编码失败不影响已经出来的，最后统一报。
- **磁盘能自己收拾**：素材页底部显示分析缓存 / 缩略图 / 工作目录各占多少、磁盘还剩多少。
  「清理缓存」要连点两次才生效（`confirm()` 在 WebView2 里可能被拦，不能靠它）。
  只清这三个白名单目录，成片、整季、总纲、台账一个都不碰；任务在跑时直接拒绝——`_work` 里正有文件在被 ffmpeg 读。
  **页面内核缓存（`gui_out/_webview`，实测 100MB+）不在这个按钮里**：窗口一开文件全被锁死，
  做了也是假按钮。它在客户端**启动前**自动清（超过 150MB 才动），只删 `Cache` / `Code Cache` /
  `GPUCache` 这类纯缓存目录，不动 Local Storage。
- **前端报错会写进日志**：客户端版没有控制台，`window.onerror` 和 `unhandledrejection` 都会 POST 到 `/api/log`，
  落到 `gui_out/app.log`，前缀「前端：」。不然用户只会说「白屏了」，而日志里干干净净。
- 界面的总纲是**异步任务**：跑的时候日志实时刷（把 `series.build` 的 print 转成了日志），
  但进度条不细分——因为转写进度是 `\r` 刷新的，逐行转日志会刷屏，所以过滤掉了。

## 二十、常见问题

**切片会不会被判搬运？**
会。切片只是原料。平台判"搬运"看的是有没有实质再创作——解说、字幕、剧情重组、观点输出。工具只帮你把原料整理好。

**字幕烧上去没反应 / 位置全错？**
先看输出里的 `字幕匹配 N/M`。匹配上了但时间对不上，多半是字幕文件本身和视频不是同一版片源，工具不负责校正这种偏差——用播放器对一下首句出现时间，整体平移字幕文件。

**字幕是乱码方框？**
字体缺字。`--sub-font "Microsoft YaHei"` 或 `--sub-font "SimHei"`，别用英文字体。

**BGM 听不见 / 完全盖住原声？**
`--bgm-vol` 调。人声类内容 0.2–0.3，纯音乐类 0.4–0.6。开了 `--duck` 可以在人声段压到更低（比如 0.4 配 duck，观感比 0.25 不 duck 更好）。

**加了 BGM 后音量忽大忽小？**
BGM 原始响度差异大。先在剪辑软件里把 BGM 统一到 -16 LUFS 左右再喂给工具，比调 `--bgm-vol` 有效。

**界面里点「出片」报 BGM 文件不存在，但路径明明是对的？**
已修。`assemble` 里相对路径的基准是工作目录 `_work/`，用户给的音乐路径会被拼到那里去。
现在界面在写配置前先 `resolve()` 成绝对路径。命令行如果自己写清单，`BGM:` 那行也建议写绝对路径。

**解说片烧了字幕，但一条字幕都没出来？**
先确认 `字幕` 不是 `off`/`none`；再看工作目录 `_work/<名字>/字幕.srt` 存不存在、有没有内容。
SRT 格式要求条目之间空行、**末尾也要有空行**——手工编辑这个文件时容易删掉末尾空行，
libass 的表现为「不报错，就是不出字幕」，比报错更难查。

**字幕和语音差半句话？**
解说片的时间轴是按文案字数分的（字多的句子分到更长的时间），不是按 TTS 实际发声点。
差得多说明 TTS 的 `--rate` 和估算差太大，或者文案里混了很长的数字/英文（TTS 念这些比字数估算慢）。
量小不用管，量大就把 `--rate` 往回调一点重配一次。

**三版文案分数都很低，选哪版？**
选分高的，但把「并排看」打开扫一眼。分数低通常意味着三版都缺段或者都超字数——
这时候改 `--seconds` 或者把 `--context` 写详细一点重跑，比硬选一版强。

**花字没出现 / 位置不对？**
`--title-start` 是**相对正片起点**的，不含片头。如果开了 `--speed`，花字时长会跟着等比缩短（内容对齐，但墙钟时间变短）。位置不对用 `--title-pos` 或 `--title-y 0.25` 直接给比例。

**花字太大挡住人脸 / 太小看不清？**
调 `--title-size`（默认 96，是 1920 高度下的像素）。竖屏封面区域一般 90–120 比较合适，底部要留出字幕位置，用 `--title-pos top`。

**中文变成方框？**
字体没找到。工具会自动在系统里找 微软雅黑/黑体/Noto CJK，都没有就显式指定：`--title-font "C:/Windows/Fonts/msyhbd.ttc"`。

**花字太长排成四五行？**
`--title-size` 调小，或者标题写成两句、用 `\n` 断行。默认超过 3 行会自动缩字号，但缩到 18px 就不再缩了（再小也看不清）。

**多规格出片太慢？**
规格数是乘数，不是加数。真要省时间，先出一个主规格投放，跑起来看数据再补其他尺寸。

**总纲里的角色名还是错的？**
先看 `总纲.md` 末尾的「已自动校正的专名」——那里列了模型改过什么，对不上就手工改回去（程序不会覆盖你的改动）。
改不动的那几个用 `--names "原名=译名"` 一次性钉死，或者直接改译名表里「原名」那一列。
名字错多半是 ASR 的问题：`small.en` 对科幻/奇幻专名的错误率能到 20%，换 `medium.en` 会明显好转
（实测同一段音频，small 漏掉了整句 `If more Klingons are on the way`，medium 听到了），代价是慢 2~3 倍。

**转写要不要一开始就用大模型？**
不必。总纲只用采样（7 分钟/集），做完一次反复复用；真正影响成片的是文案。
只有在你发现「同一个角色被写成两个人」「主角名字明显不对」的时候，才值得换 `medium.en` 重跑总纲。

**片头片尾拼接后音画不同步？**
极少数源文件时间戳异常。先重封一遍：`ffmpeg -i 片头.mp4 -c copy -fflags +genpts 片头2.mp4`。

**能去水印吗？**
不做。授权素材本不该带别人的水印，带了说明素材来源有问题，那是要去换素材而不是去水印。

**能不能直接连平台后台自动拉素材？**
不能，也不打算做。后台有登录态和频率限制，自动化拉取违反用户协议。素材下载这步人工做，量大让剧方打包给你。

## 二十一、打包成 exe（`djkit.spec`）

```bash
打包exe.bat                      # 一键：没装 PyInstaller 会先装上
# 等价于
python -m PyInstaller djkit.spec --noconfirm
```

产物：`dist/djkit/djkit.exe`，整包约 **340 MB**，双击即用，目标机器**不需要装 Python**。

```
dist/djkit/
  djkit.exe                       ← 双击这个
  _internal/                      ← 解释器 + 依赖 + ffmpeg + 页面
    djkit/web/                    ← index.html / app.js / style.css
    imageio_ffmpeg/binaries/ffmpeg-win-x86_64-v7.1.exe
    ctranslate2/ctranslate2.dll
  gui_out/                        ← 首次启动自动创建，产物都在这里
```

### 为什么是 one-folder 而不是 one-file

- one-file 每次启动都要把 340MB 解到临时目录，冷启动 20 秒起；而转码本来就在等 I/O，不能把时间浪费在这。
- one-file 的临时目录每次都变，`webview` 的 `storage_path` 跟着变，等于每次启动都丢本地状态。
- one-folder 出问题时能直接看到 `_internal` 里少了哪个 dll，one-file 只能瞎猜。

### 打包后必须改的三处路径

| 位置 | 源码运行 | 打包后 |
|---|---|---|
| `gui_server.OUT_ROOT` | `cwd / gui_out` | `exe 所在目录 / gui_out` |
| `gui_server.HERE` | `djkit/` 源码目录 | `_internal/djkit/`（datas 里映射成同名目录） |
| `run_explainer` 的 base | `Path.cwd()` | `OUT_ROOT.parent` |

判断条件是 `getattr(sys, "frozen", False)`，见 `gui_server.app_root()`。
不改的话产物会落在 `C:/Windows/System32/gui_out` 之类的地方（取决于从哪儿双击），用户永远找不到。

### 几个坑

- **`console=False` 之后 stdout 是空的**。PyInstaller 各版本行为不一（有的给 `None`，有的给一个「能写但谁都看不到」的对象），
  所以 `launch.py` 里不判断 `is None`，frozen 时一律把 stdout/stderr 换成 `gui_out/app.log`。
  否则双击闪退时**一个字的线索都没有**。
- **UPX 必须关**。压过的 `ctranslate2.dll` 会在加载时报「不是有效的 Win32 程序」，报错位置和真因差得很远。
- **`webview` 的后端是动态加载的**，静态分析看不到，必须写进 `hiddenimports`：
  `webview.platforms.edgechromium`、`webview.platforms.winforms`、`clr`、`pythonnet`。
- **`imageio_ffmpeg` 的 ffmpeg.exe 在包内的 `binaries/` 下**，普通二进制收集扫不到，得用 `collect_data_files`。
- **`excludes` 里排除 Qt 全家桶 / pandas / matplotlib / scipy**。不排的话体积直接翻倍，而且 Qt 会和 pywebview 抢 GUI 后端。
- **`multiprocessing.freeze_support()` 必须调用**，否则某些依赖新起进程时会无限递归开新 exe。
- `djkit` 自己的模块用 `collect_submodules("djkit")` 全量塞进去：整个项目有十几处函数内 `import`（为了少加载模型），
  静态扫描未必都能跟到，漏一个就是运行时 `ModuleNotFoundError`。

### 打完包怎么验

```bash
dist\djkit\djkit.exe
type dist\djkit\gui_out\app.log
```

日志里应该有三行：`ffmpeg <路径>`、`[app] 服务已起`、`[app] 桥接就绪，页面已连上`。
第三行最关键——它是页面里的 JS 主动调 `ping()` 打回来的，等价于「窗口没白屏、桥能用」。

### 仍然需要在目标机器上的东西

- **WebView2 运行时**。Win10 1803+ / Win11 自带；老机器装一次：
  https://developer.microsoft.com/microsoft-edge/webview2/
- **转写模型**。首次转写会下到 `%USERPROFILE%\.cache\djkit\models\`（0.5–1.5GB），不随 exe 打包——
  打进包里会让体积再翻一倍，而且换模型还得重新打包。
- 联网。文案走 LLM、配音走 edge-tts，都是在线服务。
